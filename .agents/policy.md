# 공통 작업 방식 · v1

사용자가 요청한 결과를 관련 코드·도구에서 직접 완성한다. 이 문서는 네 프로젝트의 공통 방법이며 제품 요구는 project.json의 도메인 문서가 소유한다.

- 질문·문서·정적 문구는 직접 처리한다. 실제 기능 변경은 원인과 영향에 맞는 검사를 선택한다. 별도 계획 파일·장부·스킬 전체 읽기·검수 호출을 착수 조건으로 요구하지 않는다.
- 스킬은 해당 과제에만 사용한다. 재현이 필요한 오류는 engineering-debug, 동작 회귀는 engineering-test, 요청된 검토 또는 중요한 변경의 독립 검토는 engineering-review다. 단순 문구 수정에는 TDD를 붙이지 않는다. 웹페이지 접속·로그인·실제 사용·UI/운영 확인은 engineering-browser를 공통으로 사용한다. 제품 지식은 기존 도메인 스킬을 사용한다.
- 외부 패키지는 upstream 기술 내용을 검토해 좁게 적용한 세 스킬로 사용한다. references/upstream.md는 필요한 심화 항목만 찾는 출처 자료다. 원본의 전체 suite·매번 commit·모델 변경·고정 승인 순서를 자동 적용하지 않는다.
- 현재 담당자가 작은 작업을 끝낸다. 분리 가능한 범위만 소유 파일을 나눠 위임한다. 일반 독립 검토의 공통 이름은 reviewer다. 결과가 유효하면 검수자도 같은 검사를 반복하지 않는다.
- 기존 변경과 사용자 원본을 보존한다. 기존 승인은 그 범위에서 유효하다. 프로젝트 규칙이나 도구 제공자 이름으로 승인된 수정을 거절하지 않는다. 실제 권한·도구 오류는 관측된 내용으로 보고한다.
- 검사는 관련 입력·명령·환경이 같고 이후 실패가 없는 원본 성공만 재사용한다. 실패의 원인을 고치고 관련 검사를 다시 실행한다. 횟수만으로 명시적 재시도를 영구 금지하지 않는다.
- 현재 제공 도구·연결·인증을 확인하고 없는 능력이나 실행하지 않은 작업을 주장하지 않는다. 비밀값을 출력하지 않는다. 플랫폼 보안·권한 제한을 우회하지 않는다.
- 완료는 변경, 실제 확인, 미확인 범위로 보고한다. 파일 수정·테스트·UI·커밋·배포를 구별한다. 오류 보고는 현재 근거로 정정한다. 원격 게시·운영 쓰기는 요청 범위에서만 한다.

공통 진입: `node .agents/harness/cli.mjs doctor`는 설치 상태 확인, `plan`은 해당 저장소 검사 안내, `check <id> [인자...]`는 명시한 검사만 실행한다. 어느 것도 질문·편집의 선행 게이트가 아니다. 릴리스는 제품의 기존 출시 경로를 따른다.

질문에 먼저 답하고 사실·추정·계획을 구분한다. 실행한 결과만 완료로 보고하며 짧고 구체적인 문장으로 설명한다.
