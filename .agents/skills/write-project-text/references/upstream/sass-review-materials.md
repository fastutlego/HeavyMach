# Sass 원고·이미지 검수 전달

원문·생성 이미지·OG·검수 자료를 보여 달라는 요청의 기본 전달은 ChatGPT Sites다. 최신 요청이 chat-only·local-only 또는 다른 형식을 지정하면 따른다. 단순 사실 질문, 코드 상태, 스킬·정책 정리는 사이트 제작 사유가 아니다. 일반 구현·진단은 설치된 Agent Skills를 사용하고 이 스킬은 자료 보존과 전달 범위를 담당한다.

1. 대상 원문·이미지·기존 Site를 확인한다. 같은 검수 작업의 Site는 갱신하고 무관한 Site에 자료를 섞지 않는다. 원문 전체, 이미지 전체, 또는 대응 관계를 보여 달라는 요청의 범위를 그대로 구성한다.
2. 현재 세션의 `sites:sites-building`·`sites:sites-hosting`을 찾아 공식 절차로 제작·배포한다. 이미 읽은 지침은 재사용하고 캐시 경로·도구 인자를 추측하지 않는다. 이 요청은 해당 자료의 비공개 검수 제공을 포함하며 전체 공개나 타인 공유로 확대하지 않는다. 기본 접근은 사용자 본인이고 실제 접근 범위는 공식 호스팅 절차로 확인한다.
3. 제목·문단·순서·문장·문장부호를 보존한다. 보고를 요약·윤문·번역 허가로 해석하지 않는다. 요청된 의견·수정안은 원문·후보·승인본과 구분한다.
4. 이미지는 실제 생성·승인 파일만 사용한다. 재생성·편집 없이 비율과 전체 화면을 보존하고 원본 크기로 볼 수 있게 한다. 호수·버전·파일 대응과 전체 수량을 확인하며 누락·실패를 대체 이미지로 숨기지 않는다. 파일을 함께 보관하거나 확인된 지속 URL을 쓰고 로컬·임시 서버·만료 서명 URL에 의존하지 않는다. 범위 밖 개인 자료·계정·토큰·환경 파일은 넣지 않는다.
5. 본문·이미지 범위, 빌드와 공식 배포 `succeeded`, 실제 접근을 증거로 연결한다. 검사는 해당 과제의 단일 reviewer가 Sites 절차와 사용자 범위에 따라 수행한다. 로컬 HTML·PR·SHA·인라인 미리보기는 배포 링크를 대신하지 않는다.
6. 최종 답변 첫 부분에 실제 Site 링크, 볼 수 있는 자료, 비공개 로그인 필요 여부를 적는다. 갱신 응답에도 링크를 다시 넣는다. 도구 부족·배포 실패는 사용 가능한 공식 도구를 확인한 뒤 실제 차단 사유와 미배포 범위를 보고하고 원본·기존 Site 정보를 보존한다. 실패한 URL을 완료 링크로 제시하지 않는다.

Site `project_id`는 `.openai/hosting.json`에 보존한다. 인계에는 배포 URL·소스 위치·원문과 이미지 출처·대상 범위를 남기며 비밀 인증정보는 제외한다.
