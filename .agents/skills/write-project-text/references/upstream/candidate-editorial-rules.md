### 7.5 공개 편집면의 존재 목적과 카피 원칙 (사용자 확정, 2026-08-22)

v2는 뉴욕타임스의 시각적 정보 위계를 참고한 **최웅주 의원의 의정활동 보고·활동 발표 매체**다. 시스템 개발 과정, 수집 파이프라인, 관리자 업무 또는 AI 처리 절차를 방문자에게 설명하는 제품 문서가 아니다. 방문자가 보는 문장은 프로페셔널한 정치인이 시민에게 자신의 업무와 의정활동을 정확하고 읽기 좋게 전한다는 목적에 복무해야 한다.

적용 범위는 `/renewal-2026/**`의 접속 화면, header·nav·footer, 빈 상태·오류, 본문·캡션·영상 안내, DB에서 불러온 게시 콘텐츠, 향후 AI API가 발췌·요약·재가공한 공개 콘텐츠 전부다.

공개면에는 다음 유형을 두지 않는다.

- **과잉 편집 메타카피**: 자료를 어떻게 모으고 검수했다는 자기설명
- **운영 프로세스 노출형 카피**: 관리자 승인, 상태값, 자동 게시 금지, DB·챗봇 반영 절차
- **방어적·자기참조적 편집문구**: 독자가 묻지 않은 내부 판단 기준과 선제적 변명
- **컴플라이언스 문체의 본문 침범**: 공약 이행 여부 면책, 법무·감사 보고서식 헤지, 구현 방식 설명
- **과잉 수사화된 단문형 카피**: 잠언체·경구체, 짧은 문장을 교훈이나 선언처럼 만드는 문체. 제목·도입·본문·UI·결말 모두에서 기능·사실 대신 추상적 가치나 장엄한 선언을 넣지 않는다.

짧고 직접적인 기능·사실 안내와 원문에 일치하는 직접 인용은 보존한다. 홍보문·단문 요청을 격언 형식의 요청으로 해석하지 않고, 삭제한 수사를 다른 비유·교훈으로 채우지 않는다. 이 규칙은 관리자 보고서에도 적용한다.

공개면에 남길 수 있는 것은 의정활동의 사실, 발언·정책의 핵심 내용, 날짜·직위·지역, 활동 사진·영상의 내용 설명, 원문으로 가는 간결한 출처 링크다. `관악구의회 원문`, `공식 프로필`처럼 출처를 확인하는 링크는 유지하되 수집·승인 과정은 관리자 화면과 운영 문서에만 둔다.

DB 원문을 그대로 발췌하든 사람이 편집하든 AI API가 추가 편집·요약하든 이 원칙은 약화되지 않는다. AI는 공개 카피의 작성 수단일 뿐 별도 예외가 아니며, 게시 경계에서 동일한 편집 정책과 관리자 사실 검수를 통과해야 한다.

문서 선언만으로 집행됐다고 보지 않는다. Web의 `scripts/verify-v2-public-copy.mjs`가 하드코딩된 공개면을 검사하고, `src/shared/content-v2/editorial-policy.ts`가 `published` DB 입력과 렌더 경계를 검사한다. 문자열 검사는 알려진 재발을 막는 최소 센서이므로, 의미상 자기참조·면책 문구는 사람의 편집 검수에서도 제거한다.

#### 7.5.1 공개 글의 편집 레퍼런스 — The New York Times (사용자 확정, 2026-08-22)

뉴욕타임스는 v2의 시각적 정보 위계뿐 아니라 **웹페이지에 게시되는 글의 논조, 논리적 전개 방식, 말투를 정하는 편집 레퍼런스**다. 이는 영문 문장이나 특정 기사를 번역·모사하거나 뉴욕타임스의 브랜드·편집권위를 차용한다는 뜻이 아니다. 이 프로젝트가 한국어 의정활동 매체에 맞게 번역해 적용할 기준은 다음과 같다.

- **논조**: 홍보문·보도자료식 찬양보다 확인 가능한 활동과 발언을 앞세운다. 중요성을 과장하는 형용사 대신 날짜, 회의, 안건, 발언, 조치, 수치와 원문 근거로 독자가 의미를 판단하게 한다.
- **논리적 전개**: 제목과 리드에서 핵심 사건을 제시하고, 초반에 왜 중요한지 설명한 뒤, 배경 → 최 의원의 구체적 활동·발언 → 근거·인용 → 현재 상태와 다음 맥락 순으로 전개한다. 시간순 나열만 하거나 결론 없는 자료 요약으로 끝내지 않는다.
- **말투**: 짧고 정확하며 절제된 한국어 기사 문장을 기본으로 한다. 선거 구호, 빈 상찬, 과도한 존칭, 관료적 보고서 문체, AI 특유의 상투적 결론과 독자에게 운영 과정을 설명하는 말투를 쓰지 않는다.
- **제목·리드**: 제목은 실제 행위와 쟁점을 구체적으로 드러내고, 리드는 누가·언제·어디서·무엇을·왜 했는지를 가능한 범위에서 압축한다. 클릭을 유도하려고 원문보다 강한 인과·성과·갈등을 만들지 않는다.
- **본문**: 한 문단에는 하나의 중심 주장만 둔다. 핵심 주장과 직접 인용은 불변 원문과 locator로 역추적돼야 하며, 사실·인용·해석·향후 계획을 문장 수준에서 구분한다.
- **의원 매체로서의 관점**: 최 의원의 활동과 문제의식을 중심에 놓되, 공식 기록으로 확인되지 않은 성과나 타인의 평가를 최 의원의 업적으로 전환하지 않는다. 정치적 입장은 발언·제안·행동의 내용으로 보여주고 편집자가 대신 과장하지 않는다.

콘텐츠 유형별 상세 전개 문법, 운영용 AI 하네스, 품질평가와 개발 순서는 `../planning/개발계획_2026-08-22_v2_편집에이전트_하네스.md`가 담당한다. 공개 카피를 생성하는 사람·코드·AI는 모두 이 절을 상위 계약으로 따른다.

#### 7.5.2 관리자·보고서 문장 규칙 (사용자 확정, 2026-08-24)

관리자 화면과 의원 공유 보고서는 공개 기사와 목적이 다르므로 수집·승인·게시 상태와 남은 위험을 숨기지 않는다. 다만 내부 구현어를 그대로 나열하거나 방어적·법무식 문장으로 책임을 회피해서는 안 된다. 개발자가 아닌 사람도 한 번에 현재 상태와 다음 행동을 이해할 수 있어야 한다.

- 결론과 행동을 먼저 쓴다. `정상`, `확인 필요`, `다시 실행`, `공개 중지`, `복원`처럼 지금 상태와 가능한 동작을 첫 문장에 둔다.
- 쉬운 업무 이름을 먼저 쓴다. `근거 사슬`은 `원문과 연결 자료`, `snapshot`은 `지식본/저장본`, `revision`은 `판/작업본`, `materialize`는 `사람이 고칠 작업본으로 옮기기`로 표현한다.
- 원문 ID, 해시, 모델명, 토큰 수처럼 운영에 필요한 기술 정보는 삭제하지 않고 `기술 정보 보기` 같은 보조 영역으로 내린다.
- 사실, 현재 상태, 관리자가 할 수 있는 동작, 아직 만들지 않은 기능을 분리한다. 일부만 구현된 메뉴를 완료로 표현하지 않는다.
- 과잉 컴플라이언스 문체, 선제적 변명, 독자가 이해할 수 없는 축약어, 화면만 존재하는 기능을 실제 동작처럼 보이게 하는 문장을 금지한다.

구현별 CRUD 판정과 후속 과제는 Web 저장소의 `docs/admin-v2-control-audit.md`가 담당하며, 알려진 불명확 표현은 `scripts/verify-admin-plain-language.mjs`가 배포 전에 차단한다.
