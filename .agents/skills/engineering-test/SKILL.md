# engineering-test

기존 테스트 프레임워크와 가장 작은 실행 명령을 먼저 확인한다. 실제 결함이면 변경 전 실패를 확보하고 수정 후 같은 행동을 검증한다. 이미 수정된 코드를 과거 RED 영수증을 만들려고 되돌리지 않는다. 사용자 관측 결과·경계·부작용을 검증하고 구현 문장이나 파일 유무만 검사하지 않는다. 테스트 없이 수정해야 하는 제약이 있으면 실행 범위를 사실대로 밝힌다. 관련 없는 suite/build/browser를 매 단계 반복하지 않는다. 데이터를 쓰는 회귀 검사는 운영과 분리된 대상 및 연결 경계를 확인한 뒤 실행한다. `.env.local`이나 `isolated`라는 이름만으로 격리를 가정하지 않는다.

비동기·mock·flaky·경계 사례 설계가 필요할 때 [원본](references/upstream.md)의 해당 절만 읽는다. 원본의 매회 full suite와 commit 예시는 보편적 의무가 아니다. 실제 출시는 제품의 전체 release 기준을 유지한다.

이 파일은 Addy agent-skills 0.6.12를 프로젝트에 맞게 수정한 적용본이다. 원문과 MIT 라이선스는 references에 보존했다. 공통 작업 방식은 .agents/policy.md를 따른다.

브라우저에서 확인할 동작은 공통 engineering-browser를 따른다. 원본 references의 특정 Chrome DevTools MCP·별도 미설치 스킬·매번 링크 이동 재승인 요구는 적용본의 실행 계약이 아니다. 도구와 승인은 현재 세션 및 사용자 요청으로 판단한다.
