# 원문과 자산 전달

사용자 지정 chat-only/local-only/다른 형식이 우선이다. 그 외 “원고 보여줘”, “이미지 보고해”, “검수하게 올려”는 기존 보고 페이지에 요청 자료 전체를 전달한다. 이 저장소의 `docs/report-site.md`와 현재 제공된 Sites 도구/스킬을 확인한다. 도구 인자는 실제 스키마를 따른다.

기존 Site `appgprj_6addbf55aea081918d3d182d7e496e88`, source repo main을 재사용한다. 사용자 2026-10-27 지시: 보고서는 이 사이트 하나에 통합한다. 새 보고서는 기존 사이트의 하위 페이지로 추가하고 첫 화면 `index.html#reports`의 전체 목차에 등록한다. 모든 보고서에서 전체 목차로 돌아갈 수 있게 하며, 사이트의 HTML 보고서 목록과 목차를 대조해 빠진 페이지가 없도록 검사한다. 실제 `.openai/hosting.json`, 로컬 소스 SHA와 Sites 상태를 확인한다. Git 원격이 있으면 최신 원격도 확인하고, 없으면 Sites source helper가 제공하는 원본 연결을 사용한다. 원격 부재만으로 승인된 작업을 거절하거나 새 원격을 임의 생성하지 않는다. 새 Site·원격·스토리지·공개 확대를 임의 추가하지 않는다. 기본은 사용자 본인의 비공개 검수이며 실제 접근 범위를 확인한다.

- 요청 원문 전체·문단 순서·구두점·대응 파일을 보존한다. 요약/번역/윤문으로 대신하지 않는다. 수정 제안은 원문과 구분하며 원문·후보·승인본의 수량·호수·버전을 대조한다. 누락/생성 실패는 공개하고 대체 이미지로 숨기지 않는다.
- 실제 승인 이미지/캡처를 사용하고 보고만을 위한 재생성·크롭·수정을 하지 않는다. 원본 해상도·비율을 유지하며 반응형 표시와 원본 보기를 제공한다.
- 현재 Sites 업로드 경로로 지속 가능한 자산 URL을 쓴다. 로컬 경로·임시 preview·곧 만료되는 URL을 최종 이미지로 쓰지 않는다. 원고·로그·설정의 비밀정보를 노출하지 않는다.
- 실제 콘텐츠를 바꿨으면 영향에 맞는 빌드·브라우저 확인과 배포 상태를 확인한다. 브라우저 선택·로그인 세션·오류 분류는 공통 `engineering-browser` 스킬을 따르며 Unity 관찰은 게임 도메인 검증으로 구분한다. 미실행 화면 검사를 PASS로 표시하지 않는다. 기존 자료와 Site는 실패해도 보존한다.

Git source 반영·버전 저장·게시 배포·사용자 접근은 각각 별도 결과다. 지침 변경은 게시하지 않는다. 실제 사이트 전달 완료는 요청 자료 전체, 관련 빌드 결과, 공식 배포 상태 `succeeded`, 실제 접속 URL로 확인한다. 로컬 HTML·PR·commit·preview만으로 완료라 하지 않는다. 최종 응답 앞에 클릭 가능한 URL, 자료 범위, 로그인 필요 여부를 적으며 갱신 시에도 링크를 제공한다.

가용 도구가 없으면 그 기능의 미완료·정확한 원인을 알리고 가능한 작업은 계속한다. 인계에는 project_id·URL·source 위치·원문/이미지 출처·범위와 미해결 항목만 남기고 비밀 인증정보는 남기지 않는다. 별도 검수자는 필요할 때만 요청 자료·게시 화면·접근 범위를 대조한다.
