# 럭스루나에 전투기 3종 추가 계획

2026-10-27. 요구 ID `HM-LUX`. 혼자 구현·검증 가능한 범위다. 기체 3종, 금색 조종석 유리, 묶음 연사와 증원을 구현했다. 아이폰·아이패드에 치트·정식 앱 4건을 업데이트 설치하고 실행했다. 코어 21개, 시뮬레이터 4개, iPhone 4개, iPad 4개, native Mac 5개 검사가 통과했다. [그림과 배치표](public/lux-lunae-design-20261027.md).

## 기준 버전과 작업 위치

기존 작업은 `feat/auto-aim-ipad-validation → develop → main` 순서로 병합했다. develop은 `e9376910`, main은 `f0c4432f`이며 main 병합에 주석 태그 `v0.11`을 달고 원격에 푸시했다. 기존 태그는 유지했다. 새 작업은 develop에서 분기한 `feat/lux-lunae-fighters`에서 진행한다. 자동조준·C 삭제 검증은 기존 유효 결과를 재사용했다. 신규 전투기 구현·검사는 이번 릴리스에 포함되지 않는다.

## 사용자 요구

- ACE COMBAT 8 럭스루나에 편대 도색을 적용한 F-22, Su-57, MiG-31을 추가한다.
- 가장 내구력이 높은 헬기의 1.7배를 각 기체에 적용한다.
- 기존 헬기 또는 VTOL의 미사일 계열 무기를 재사용한다. 미사일 비행 속도는 25% 높인다. 연사속도는 최초 25%에서 사용자 후속 지시로 10% 증가로 낮췄다.
- 보스전 순서에 따라 2/4/6/8대가 등장하며 최대 8대로 제한한다.
- 보스전 직전 미션의 마지막 월드 구간에는 4대가 등장한다.
- 기존 스폰 항목을 대체하지 않고 추가한다. 실제 기체의 형태와 기존 게임의 색조·질감을 유지한다.

## 내구력과 무장

원본 `Resources/RawData`를 `GameData::loadDirectory`로 읽었다. `Heli009`, `Heli010`의 HP가 각각 450으로 일반 헬기 10종 중 최대다. 세 기체 모두 **450 × 1.7 = 765**를 사용한다. VTOL F35B가 참조하는 다른 기체의 HP를 헬기 최대값으로 사용하지 않는다.

| 기체 | 원본 무기·사용자 | 확정 무장 | 피해/발사 수 | 비행 속도 | 재발사 간격 | 묶음 안의 간격 |
|---|---|---|---|---|---|---|
| F-22 | E_Wpn_ASM / Heli001~010·Yak141 | 단발 미사일 3연사 | 25 / 3발 | 160 → 200 | 5 → 약 4.545초 | 약 0.455초 |
| Su-57 | E_Wpn_ASM / Heli001~010·Yak141 | 단발 미사일 3연사 | 25 / 3발 | 160 → 200 | 5 → 약 4.545초 | 약 0.455초 |
| MiG-31 | E_0604_Wpn / VTOL F35B | 2발 × 3묶음 | 100 / 6발 | 160 → 200 | 5 → 약 4.545초 | 0.5 → 약 0.455초 |

연사속도 10% 증가는 시간 간격을 `1.1`로 나눈다. 신규 무기의 재공격 데이터는 `5/1.1`, 연속탄 간격은 `0.5/1.1`, MiG-31 묶음 간격은 `1/1.1`초다. AI 조준·준비·다음 공격 대기도 신규 기체에 한해 `1/1.1`배를 사용한다. 발사 시각 검사에서는 60Hz 갱신의 최대 1프레임 오차를 허용한다. 탄속은 `160×1.25=200`을 유지한다.

신규 무기 ID 3개에 원본 정의를 복사한다. 해당 복사본의 속도와 간격만 변경한다. 발당 피해, 분산, 중력, 수명 7초, 피격·폭발 규칙과 음향은 원본 값을 사용한다. 수명이 같으므로 빨라진 속도에 따라 이동 가능한 거리는 늘 수 있다. 기존 `E_Wpn_ASM`, `E_0604_Wpn`을 직접 수정하지 않는다. F-22·Su-57은 3발, MiG-31은 2발씩 3묶음을 발사한다. MiG-31 묶음 사이 대기는 약 0.909초다.

## 후속 질문: 미사일 묶음 연사

사용자의 후속 지시로 F-22·Su-57의 3발 연사와 MiG-31의 2발×3묶음을 확정했다. F-22·Su-57은 약 0.455초 간격이다. MiG-31은 약 0.455초 간격으로 2발을 쏜 뒤 약 0.909초 기다리고 다음 묶음을 시작한다. 한 공격의 총 피해는 각각 75, 75, 600이며 실제 피해는 명중 수에 따라 달라진다.

`WeaponInfo`에 신규 기체용 AI 대기 배율·묶음 크기·묶음 대기를 추가했다. 기존 무기 기본값은 1·0·0이다. 발사마다 타이머나 파일 저장을 추가하지 않는다. 기존 게임 갱신에서 처리하며 일시정지 때 멈추고, 격파·스테이지 종료로 기체가 제거되면 남은 발사도 실행되지 않는다.

## 보스와 등장 구간

이 계획에서 보스전은 **미션 마지막 대형 보스전**이며 일반 서브미션의 중간보스는 제외한다. 원본의 `isBoss`는 중간보스에도 붙어 있으므로 그 플래그만으로 배치하지 않는다. 다음 표의 기체 수는 세 기종을 합친 수다.

| 순서 | 대형 보스전 / 맵 | 보스 ID | 합계 | F-22 / Su-57 / MiG-31 | 직전 서브미션 / 맵 | 직전 구간의 편성 |
|---|---|---|---:|---|---|---|
| 1 | 1-4 / Stage04 | Boss02 | 2 | 1 / 1 / 0 | 1-3 / Stage03 | 2 / 1 / 1 |
| 2 | 2-5 / Stage09 | Boss04 | 4 | 1 / 1 / 2 | 2-4 / Stage08 | 1 / 2 / 1 |
| 3 | 3-5 / Stage14 | Boss05 | 6 | 2 / 2 / 2 | 3-4 / Stage13 | 1 / 1 / 2 |
| 4 | 4-5 / Stage29 | Boss03 | 8 | 3 / 3 / 2 | 4-4 / Stage28 | 2 / 1 / 1 |
| 5 | 5-5 / Stage19 | Boss01 | 8 | 3 / 2 / 3 | 5-4 / Stage18 | 1 / 2 / 1 |
| 6 | 6-5 / Stage24 | Boss06 | 8 | 2 / 3 / 3 | 6-4 / Stage23 | 1 / 1 / 2 |
| 7 | 7-6 / Stage35 | Boss07 | 8 | 3 / 3 / 2 | 7-5 / Stage34 | 2 / 1 / 1 |

대형 보스전 44대와 직전 구간 28대를 합쳐 총 72대를 추가한다. Survival에는 추가하지 않는다. 원본 적 1,182항목과 기존 VTOL 113항목의 이름·좌표·보스 여부·순서는 보존한다.

보스 증원은 `WorldState::activateBossEncounter`의 실제 전투 시작을 사용한다. 가변 화면의 선행 생성만으로 증원을 시작하지 않는다. 보스 단계별 1회 발생 상태를 메모리에 보관하고, 일시정지·복귀·회전으로 중복 생성하지 않는다. 재시작하면 해당 스테이지 상태만 초기화한다.

직전 서브미션은 맵 오른쪽 끝에서 800 논리 단위 앞을 마지막 구간의 시작으로 사용한다. 전체 14개 구간을 원본 중간보스 전장 해제 조건과 함께 검사했다. 마지막 구간 진입 때 4대를 한 번 추가하고, 화면 폭은 조건에 사용하지 않는다. 기체 전체가 현재·이동 예정 화면의 오른쪽 바깥에서 생성된다. 보스 전장 경계는 진입 목표점에 적용한다. 가로 간격90·최대2개 고도로 들어오며 매 갱신2.5단위씩 이동한다. 화면 안 진입 목표점에 도착하면 기존 AI로 돌아간다. 진입 중에는 공격하지 않으며 pause 중에는 움직이지 않는다. 원본 헬기·VTOL의 생성 방식은 유지한다.

지원기는 일반 적으로 취급한다. 원래 보스 수와 클리어 판정은 유지한다. 보스를 먼저 처치해 클리어될 때 지원기 때문에 진행이 막히지 않게 한다.

## 그림과 움직임 연결

시안은 `Art/LuxLunae/20261027/`에 있다. 형태 참조, 도색 참조, 기존 게임 질감 참조를 분리해 내장 imagegen에 입력했다. 최초 MiG-31의 세 번째 꼬리날개와 배경 번짐은 재생성으로 수정했다. 금색 유리는 채택된 기체의 유리 부분을 imagegen으로 편집했다. 최종 원본·프롬프트·해시는 `Art/LuxLunae/20261027-gold/`, 제품 소비 파일은 `Art/Extensions/Lux_*.png`다. 프레임·동체·투명 배경을 유지했다.

확정 표시 길이는 F-22 112, Su-57 116, MiG-31 120 논리 단위다. 원본 Heli001보다 길고 Heli006보다 짧은 범위에서 세 기체의 높이를 비례 조절한다. 시뮬레이터·두 실기기에서 원본 헬기와 나란히 그려 외곽선·기체 구분을 확인했다. 기체 그림에 불꽃은 넣지 않는다. 배기 효과는 뒤쪽 엔진 위치에 별도로 붙인다.

기존 공중 적의 이동·공격 구조와 VTOL의 자세·발사점 계산을 재사용한다. 신규 기체의 자세는 이동 속도에서 계산하며 회전한 그림·미사일 발사점·피격 범위를 함께 처리한다. 필요해진 공용 그림 구조만 추출하고 기존 VTOL의 수치와 이동은 유지한다. 새로 만드는 배치·움직임 난수는 기존 적의 난수 소비 순서에 섞지 않는다.

## 구현과 검사 순서

1. 신규 기체/무기 정의와 별도 증원표를 추가한다. 원본 테이블 보존, HP 765, 미사일 속도 200, 실제 발사 간격, 72대 편성을 코어 검사로 확인한다.
2. 치트 앱에 3종 단독·혼합 8대 조건을 추가한다. 좁은/넓은 화면, 지형 고도, 앞뒤 이동·점프·사격·표적 전환을 검사한다.
3. 보스 7곳과 직전 구간 7곳을 정상 진입·재시작·중단 복귀로 검사한다. 중간보스, 선행 생성, 회전이 증원을 중복시키지 않는지 확인한다.
4. 전체 무기 20종으로 신규 기체의 피격·격파를 검사한다. 자동조준 OFF의 탄속·분산·저장 호출은 기존 회귀 검사로 확인한다.
5. iPhone·iPad·Mac에서 큰 그림/게임 크기 합성과 프레임·메모리를 확인한다. 8대 미사일 연속 발사와 기존 보스 전투가 겹치는 조건을 포함한다. 치트 확인 후 정식 앱에도 같은 코어와 에셋을 연결한다.

## 구현 결과 · 2026-10-27

`Fighters.cpp`가 원본을 읽은 뒤 신규 기체/무기만 추가한다. `GameSession`은 별도 14개 증원표를 읽고 실제 대형 보스 활성 또는 직전 구간 진입 때 한 번 생성한다. 보스 수를 늘리지 않으며 Survival에는 추가하지 않는다. 새 움직임 난수는 기존 VTOL의 기체별 난수 경로를 사용한다.

전체 코어 21/21, 시뮬레이터 4/4, iPhone 4/4, iPad 4/4, Mac 4/4와 HUD 입력 1/1이 통과했다. 3종 각각에 플레이어 20종 무기의 실제 충돌·피해 60건을 검사했다. 원본 스폰 항목과 기존 무기 값은 유지됐으며, 기존 수동 사격 25,200프레임 기록은 이전 버전과 바이트 단위로 같았다. 검사 중 발사 저장 호출은 0회였다.

기기 설치는 기존 앱을 삭제하지 않고 업데이트했다. iPhone은 localNetwork, iPad는 wired였다. 정식·치트 앱은 같은 기체/무기 코드와 에셋을 사용한다. 아직 develop/main에 병합하지 않았다.

첫 코어 실패 2건은 검사의 0/1 기반 미션 번호 혼용과 이전 중간보스 전장을 해제하지 않은 위치 이동 조건이었다. 검사 조건을 수정했다. Mac 검사의 기존 iOS 전용 `NSValue` 크기 함수는 공용 `CGSize` 배열로 바꿨다. CLI 서명 실패는 기존 Xcode GUI 서명 빌드로 완료했다. 실패 원본 로그는 보존했다.

[기기 캡처·측정](public/lux-lunae-design-20261027.md), [실행 증거](evidence/lux-lunae-implementation-20261027.json). 장시간 발열·메모리 추적과 추가된 적을 포함한 정식 난이도 전체 캠페인 밸런스 검사는 남아 있다.

## 사용자 확인 후 수정

사용자는 최초 정식 설치본을 확인하고 화면 안에서 갑자기 나타나는 현상을 보고했다. 생성점을 화면 바깥으로 옮기고 실제 이동으로 진입하도록 수정했다. 이어 연사속도를 원본 대비25% 증가에서10% 증가로 낮췄다. 기체 수·내구력·미사일 비행 속도는 유지한다. 후속 코어21개, 시뮬레이터2개, iPhone/iPad/Mac 진입 검사 각1개가 통과했다. 두 기기의 치트·정식 앱을 수정본으로 다시 업데이트했다.
