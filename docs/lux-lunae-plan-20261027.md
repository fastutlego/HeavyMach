# 럭스루나에 전투기 3종 추가 계획

2026-10-27. 요구 ID `HM-LUX`. 혼자 구현·검증 가능한 범위다. 현재 완료 범위는 원본 데이터 조사, 도색·기체 참조 확보, PNG 시안 3종과 이 계획이다. 게임 코드와 설치본에는 아직 추가하지 않았다. [그림과 배치표](public/lux-lunae-design-20261027.md).

## 기준 버전과 작업 위치

기존 작업은 `feat/auto-aim-ipad-validation → develop → main` 순서로 병합했다. develop은 `e9376910`, main은 `f0c4432f`이며 main 병합에 주석 태그 `v0.11`을 달고 원격에 푸시했다. 기존 태그는 유지했다. 새 작업은 develop에서 분기한 `feat/lux-lunae-fighters`에서 진행한다. 자동조준·C 삭제 검증은 기존 유효 결과를 재사용했다. 신규 전투기 구현·검사는 이번 릴리스에 포함되지 않는다.

## 사용자 요구

- ACE COMBAT 8 럭스루나에 편대 도색을 적용한 F-22, Su-57, MiG-31을 추가한다.
- 가장 내구력이 높은 헬기의 1.7배를 각 기체에 적용한다.
- 기존 헬기 또는 VTOL의 미사일 계열 무기를 재사용한다. 미사일 연사속도와 비행 속도는 25% 높인다.
- 보스전 순서에 따라 2/4/6/8대가 등장하며 최대 8대로 제한한다.
- 보스전 직전 미션의 마지막 월드 구간에는 4대가 등장한다.
- 기존 스폰 항목을 대체하지 않고 추가한다. 실제 기체의 형태와 기존 게임의 색조·질감을 유지한다.

## 내구력과 무장

원본 `Resources/RawData`를 `GameData::loadDirectory`로 읽었다. `Heli009`, `Heli010`의 HP가 각각 450으로 일반 헬기 10종 중 최대다. 세 기체 모두 **450 × 1.7 = 765**를 사용한다. VTOL F35B가 참조하는 다른 기체의 HP를 헬기 최대값으로 사용하지 않는다.

| 기체 | 원본 무기·사용자 | 제안 무장 | 피해/발사 수 | 비행 속도 | 재발사 간격 | 묶음 안의 간격 |
|---|---|---|---|---|---|---|
| F-22 | E_Wpn_ASM / Heli001~010·Yak141 | 단발 미사일 | 25 / 1발 | 160 → 200 | 5 → 4초 | 원본 0 유지 |
| Su-57 | E_Wpn_ASM / Heli001~010·Yak141 | 단발 미사일 | 25 / 1발 | 160 → 200 | 5 → 4초 | 원본 0 유지 |
| MiG-31 | E_0604_Wpn / VTOL F35B | 2발 연속 미사일 | 100 / 2발 | 160 → 200 | 5 → 4초 | 0.5 → 0.4초 |

연사속도 25% 증가는 시간 간격을 `1.25`로 나누는 값이다. `0.75`를 곱하면 연사속도가 33.3% 증가하므로 사용하지 않는다. 위 간격은 원본 무기 데이터 기준이다. 현재 `processWeaponAI`는 조준 대기 `0.3+0.5r`, 발사 준비 `0.05+0.4r`, 다음 공격 대기 `0.5+delay×r`을 별도로 둔다. 신규 기체에 한정해 이 대기들도 0.8배로 처리한다. 같은 입력·거리·난수에서 실제 발사 시각을 기록해 25% 증가를 검사한다. 60Hz 갱신의 1프레임 시간 오차는 따로 기록한다.

신규 무기 ID 3개에 원본 정의를 복사한다. 해당 복사본의 속도와 간격만 변경한다. 피해, 탄 수, 분산, 중력, 수명 7초, 피격·폭발 규칙과 음향은 원본 값을 사용한다. 수명이 같으므로 빨라진 속도에 따라 이동 가능한 거리는 늘 수 있다. 기존 `E_Wpn_ASM`, `E_0604_Wpn`을 직접 수정하지 않는다. F-22와 Su-57의 무기는 같고, MiG-31만 2발 연속 무기로 구분하는 제안이다.

## 후속 질문: 미사일 묶음 연사

단발 미사일을 3발 연속으로 쏘거나, 기존 2발 연속 발사를 세 묶음 반복하는 것도 가능하다. 기존 `shotCnt`와 `shotDly`는 한 묶음의 탄 수와 균일한 간격을 처리한다.

- 단발 3연사: 신규 무기의 `shotCnt=3`과 발사 간격을 지정한다. 원본 단발은 묶음 안의 간격이 0이므로, 새 3연사의 간격은 별도로 정해야 한다.
- 2발×3묶음: 총 6발이다. 2발 사이 0.4초와 묶음 사이의 간격을 구분하려면 신규 무기용 묶음 횟수·대기 처리를 추가한다. 현재 코드에서 `shotCnt=6`만 지정하면 동일 간격의 6연사이므로 2발씩 끊어 쏘는 동작과 구별한다.
- 총 피해량은 발사 수에 따라 증가한다. 기존 미사일의 발당 피해·비행·충돌·그림을 재사용한다. 현재 기체별 무장표는 최초 제안이며, 묶음 연사는 후속 선택 가능한 구성으로 기록한다.
- 발사 스케줄은 게임 갱신에서 처리한다. 발사마다 타이머·파일 저장을 추가하지 않는다. 일시정지 때 멈추고 격파·스테이지 종료 시 남은 묶음을 취소한다. 기존 헬기·VTOL과 플레이어 무기는 기존 경로를 유지한다.

## 보스와 등장 구간

이 계획에서 보스전은 **미션 마지막 대형 보스전**이며 일반 서브미션의 중간보스는 제외한다. 원본의 `isBoss`는 중간보스에도 붙어 있으므로 그 플래그만으로 배치하지 않는다. 다음 표의 기체 수는 세 기종을 합친 수다.

| 순서 | 대형 보스전 / 맵 | 보스 ID | 합계 | F-22 / Su-57 / MiG-31 | 직전 서브미션 / 맵 | 직전 구간의 편성 |
|---|---|---|---:|---|---|---|
| 1 | 1-4 / Stage04 | Boss02 | 2 | 1 / 1 / 0 | 1-3 / Stage03 | 2 / 1 / 1 |
| 2 | 2-5 / Stage09 | Boss04 | 4 | 1 / 1 / 2 | 2-4 / Stage08 | 1 / 2 / 1 |
| 3 | 3-5 / Stage14 | Boss05 | 6 | 2 / 2 / 2 | 3-4 / Stage13 | 1 / 1 / 2 |
| 4 | 4-5 / Stage29 | Boss03 | 8 | 3 / 3 / 2 | 4-4 / Stage28 | 2 / 1 / 1 |
| 5 | 5-5 / Stage19 | Boss01 | 8 | 3 / 2 / 3 | 5-4 / Stage18 | 1 / 2 / 1 |
| 6 | 6-5 / Stage24 | Boss06 | 8 | 2 / 3 / 3 | 6-4 / Stage23 | 1 / 1 / 2 |
| 7 | 7-6 / Stage35 | Boss07 | 8 | 3 / 3 / 2 | 7-5 / Stage34 | 2 / 1 / 1 |

대형 보스전 44대와 직전 구간 28대를 합쳐 총 72대를 추가한다. Survival에는 추가하지 않는다. 원본 적 1,182항목과 기존 VTOL 113항목의 이름·좌표·보스 여부·순서는 보존한다.

보스 증원은 `WorldState::activateBossEncounter`의 실제 전투 시작을 사용한다. 가변 화면의 선행 생성만으로 증원을 시작하지 않는다. 보스 단계별 1회 발생 상태를 메모리에 보관하고, 일시정지·복귀·회전으로 중복 생성하지 않는다. 재시작하면 해당 스테이지 상태만 초기화한다.

직전 서브미션은 맵 오른쪽 끝에서 800 논리 단위 앞을 마지막 구간의 시작 후보로 삼는다. 원본 지형과 마지막 중간보스의 전장 제한을 대조해 확정한다. 마지막 구간 진입 때 4대를 한 번 추가하고, 화면 폭은 조건에 사용하지 않는다. 생성 위치는 지형 높이와 맵 경계로 계산한다. 좁은 보스 맵에서도 플레이어와 겹치거나 지형 안에 생성되지 않도록 2~4개 고도와 가로 간격으로 배치한다.

지원기는 일반 적으로 취급한다. 원래 보스 수와 클리어 판정은 유지한다. 보스를 먼저 처치해 클리어될 때 지원기 때문에 진행이 막히지 않게 한다.

## 그림과 움직임 연결

시안은 `Art/LuxLunae/20261027/`에 있다. 형태 참조, 도색 참조, 기존 게임 질감 참조를 분리해 내장 imagegen에 입력했다. 최초 MiG-31의 세 번째 꼬리날개와 배경 번짐은 재생성으로 수정했다. 현재 PNG는 기획 시안이며 게임용 피격 범위나 발사점을 확정한 에셋은 아니다.

표시 길이의 첫 비교 후보는 F-22 112, Su-57 116, MiG-31 120 논리 단위다. 원본 Heli001보다 길고 Heli006보다 짧은 범위에서 세 기체의 높이를 비례 조절한다. 실제 앱에서 기존 헬기와 나란히 그려 외곽선·기체 구분을 확인한 뒤 확정한다. 기체 그림에 불꽃은 넣지 않는다. 배기 효과는 뒤쪽 엔진 위치에 별도로 붙인다.

기존 공중 적의 이동·공격 구조와 VTOL의 자세·발사점 계산을 재사용한다. 신규 기체의 자세는 이동 속도에서 계산하며 회전한 그림·미사일 발사점·피격 범위를 함께 처리한다. 필요해진 공용 그림 구조만 추출하고 기존 VTOL의 수치와 이동은 유지한다. 새로 만드는 배치·움직임 난수는 기존 적의 난수 소비 순서에 섞지 않는다.

## 구현과 검사 순서

1. 신규 기체/무기 정의와 별도 증원표를 추가한다. 원본 테이블 보존, HP 765, 미사일 속도 200, 실제 발사 간격, 72대 편성을 코어 검사로 확인한다.
2. 치트 앱에 3종 단독·혼합 8대 조건을 추가한다. 좁은/넓은 화면, 지형 고도, 앞뒤 이동·점프·사격·표적 전환을 검사한다.
3. 보스 7곳과 직전 구간 7곳을 정상 진입·재시작·중단 복귀로 검사한다. 중간보스, 선행 생성, 회전이 증원을 중복시키지 않는지 확인한다.
4. 전체 무기 20종으로 신규 기체의 피격·격파를 검사한다. 자동조준 OFF의 탄속·분산·저장 호출은 기존 회귀 검사로 확인한다.
5. iPhone·iPad·Mac에서 큰 그림/게임 크기 합성과 프레임·메모리를 확인한다. 8대 미사일 연속 발사와 기존 보스 전투가 겹치는 조건을 포함한다. 치트 확인 후 정식 앱에도 같은 코어와 에셋을 연결한다.
