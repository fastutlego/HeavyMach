# HUD 배치 편집과 자동조준 상태 표시 계획

v0.13을 develop→main으로 병합하고 태그와 [소스·자원 릴리스](https://github.com/gelb2/HeavyMach/releases/tag/v0.13)를 게시했다. main 병합은 `bc4e80c0`, develop 병합은 `3677b0a7`이다. 쉴카·퉁구스카 최종 수정본의 코어23개·시뮬레이터2개·아이폰/아이패드 각5개 검사 결과를 재사용했고, 병합된 제품 코드·에셋이 검사본과 같음을 확인했다. 릴리스 압축을 새 폴더에 풀어 자원1,498개 해시도 확인했다.

다음 HUD 작업은 **현재 그림을 기능별로 분할하고, 화면 배치와 터치 영역을 한 데이터로 계산하는 것**부터 시작한다. 그다음 게임 시작 전 배치 편집을 붙이고, 자동조준 상태 안내를 보강한다.

## 이동할 묶음과 그림 분할

첫 구현은 크기·투명도·각도 변경 없이 위치 이동을 제공한다. 연결된 장식을 함께 옮겨 금속판 위에 버튼이 붙어 있는 현재 디자인을 유지한다.

| 편집 단위 | 함께 움직일 요소 |
|---|---|
| 메뉴 | 메뉴 버튼과 받침 |
| 레벨·경험치 | LV/EXP 표기, 숫자, 경험치 바와 배경 |
| 점프 | 부스터 버튼과 받침 |
| 무기 | 무기 전환 버튼, 무기 아이콘, 탄약 숫자, 화면 테두리 |
| 상태 계기판 | 체력·재장전 바늘, 원형 테두리, 경고등, 기어 |
| 자동조준 | A 버튼, 다음 표적 버튼, 사격 버튼과 금속 받침. 세 버튼은 각각 옮길 수 있게 구성 |
| 보조 표시 | 패시브 아이콘·숫자 목록, 잠깐 나타나는 무기 선택 목록 |

계기판의 바늘·테두리를 따로 드래그하게 하지는 않는다. 메뉴창·업그레이드창·클리어 일러스트·미션 시작 문구와 월드에 붙는 표적 표지는 이번 자유 배치 대상에서 제외한다. 치트 전용 방향키는 별도 묶음으로 다루며 정식 앱에 추가하지 않는다.

원본 PNG는 보존한다. **원본 텍스처의 사각형 영역을 지정해 그리는 방식**을 우선한다. `HMMedia`에는 현재 임의 사각형을 그리는 공개 함수가 없으므로, 작은 영역을 그대로 제출하는 기능을 추가해야 한다. 프레임마다 이미지를 잘라 새 텍스처를 만드는 방식은 쓰지 않는다. 알파가 복잡한 부분은 한 번 만든 파생 그림과 분할 좌표표로 관리한다.

하단 그림에는 무기창·계기판·연결 레일이 함께 있다. 분할만 하면 잘린 금속판 끝이 보일 수 있으므로 원본 금속 질감에서 짧은 마감 부품을 만들고 실제 크기로 비교한다. 추가 그림이 필요하면 기존 점프·메뉴·무기 버튼과 나란히 놓고 확인한다. 기본 배치는 분할 전후 픽셀을 대조해 현재 모양을 유지한다.

## 배치·그림·터치를 연결하는 방법

공용 코어에 `HUDLayout`을 두고 요소 ID, 기본 위치, 그림 크기, 터치 사각형, 묶음 관계를 정의한다. iPhone·iPad·Mac은 같은 계산을 사용한다. `HMGameHUD`와 자동조준 버튼은 계산된 결과를 받아 그리며, 입력도 그 결과의 사각형을 사용한다.

기본 배치는 현재480×320 좌표를 그대로 사용한다. 사용자 배치는 안전영역의 좌우·상하 기준점과 상대 위치로 저장한다. 이미지 비율과 버튼 크기는 유지한다. 가로 회전·창 크기 변경 때 표시 위치만 다시 계산하고, 저장된 사용자의 위치를 덮어쓰지 않는다. 공간이 부족하면 일시적으로 안전영역 안에 제한하고 원래 크기로 돌아왔을 때 배치를 복원한다.

버튼이 움직이면 예전 위치의 입력 영역도 없어진다. 편집 화면에서는 버튼·게이지의 실제 영역을 표시한다. 버튼끼리 겹치거나 화면 밖에 나간 배치는 확정하지 못하게 하고 해당 영역을 표시한다. 장식끼리 맞닿는 것은 허용한다. 장식의 투명 영역은 월드 터치를 막지 않는다.

누르고 있는 중 회전·메뉴 열기·배치 변경·앱 중단이 발생하면 관련 터치를 취소하고 사격·점프 입력을 해제한다. 키보드는 기존 행동 ID에 연결하므로 버튼 위치를 바꿔도 매핑을 유지한다. 원작480 비교 모드는 기존 배치를 유지한다.

## 게임 시작 전 편집 화면

미션을 고른 뒤 시작 직전에 ‘HUD 배치’ 화면으로 들어갈 수 있게 한다. 첫 사용에서는 기본 배치와 편집 진입 버튼을 보여 주고, 이후에는 저장한 배치로 바로 시작할 수 있게 제안한다.

1. 시작할 맵과 플레이어를 준비하고 게임 시간이 흐르기 전 월드 그림을 한 번 캡처한다. 적 이동·탄약 소비·진행 저장은 발생시키지 않는다.
2. 캡처 위에 현재 HUD와 드래그 영역을 겹쳐 표시한다. 미리보기와 실제 게임은 같은 배치 계산·렌더 함수를 사용한다.
3. 손가락 또는 Mac 마우스·트랙패드로 묶음을 옮긴다. Tab으로 요소를 선택하고 방향키로 이동하는 편집도 제공한다. 편집 키는 게임에 전달하지 않는다.
4. ‘기본 배치’, ‘취소’, ‘적용 후 시작’을 제공한다. 기본 배치는 현재 초기 HUD로 돌아가며, 취소하면 편집 전 배치로 돌아간다.
5. 화면 크기가 바뀌면 필요한 시점에만 미리보기를 다시 만든다. 편집 중 매 프레임 GPU 화면을 읽거나 캡처 파일을 쓰지 않는다.

배치는 iPhone·iPad·Mac별로 따로 저장한다. 정식·치트 앱의 저장도 분리한다. 버전 번호가 있는 별도 HUD 설정을 사용해 기존 게임 진행 파일을 바꾸지 않는다. 드래그 중에는 메모리만 갱신하고 **‘적용’ 때 한 번 저장**한다. 손상되거나 지원하지 않는 설정은 기본 배치로 열며 파일을 즉시 덮어쓰지 않는다.

## 자동조준 상태를 알리는 방법

표시만 보강한다. 표적 선택·전환·해제, 포신 조정, 탄속·분산·피해·발사 판정은 현재 코드를 유지한다.

| 실제 상태 | 제안할 표시 |
|---|---|
| 수동 모드 | A 버튼의 꺼진 모습 유지. 별도 조준 상태 문구 숨김 |
| 자동 모드, 대상 없음 | A 버튼 옆 작은 상태판에 `NO TARGET` |
| 대상 있음, 포신 조정 중 | `TRACK`와 기존 표적 테두리 |
| 현재 발사 조건 충족 | `LOCKED`와 기존 표적 테두리. 포신 조정과 발사 조건 충족을 표시 |
| 현재 발사 조건 미충족 | `BLOCKED`. 탄도 해를 찾지 못한 경우와 경로가 막힌 경우를 함께 포함 |
| 화면 밖 대상 | 안전영역 가장자리에 방향 화살표와 작은 표적 기호. 상태판은 계속 표시 |
| 화면 안이지만 지형 뒤에 가려 보이지 않는 대상 | 대상 위치의 테두리와 연결선을 지형 위에 표시. 발사 가능 상태와 따로 표현 |

현재 `AimStatus::blocked`에는 탄도 해가 없는 경우도 포함된다. 이것을 전부 ‘지형에 가림’이라고 표시하면 잘못된 안내다. 상태판은 기존 상태값을 그대로 읽고, 지형 가림 표현이 필요할 때는 표시용으로 지형과 표적의 겹침을 검사한다. 이 값은 조준·사격 로직에 전달하지 않는다.

상태판은 기존 금속 받침·노란 기호·스텐실 글자에 맞춘다. 화면 밖 화살표는 HUD 버튼과 겹치지 않는 가장자리를 찾는다. 색과 함께 글자·형태를 사용하며 깜빡임은 표적 획득 순간에만 짧게 준다. 먼저 대상 없음·화면 밖·발사 불가 세 장면의 실제 크기 시안을 비교한다.

## 구현과 검증 순서

| 단계 | 구현 | 통과 조건 |
|---|---|---|
| 1. 기본 배치 공통화 | 원작·자동조준 버튼 좌표를 `HUDLayout`으로 모으고 그림 영역을 분할 | 기본 화면 비교, 원래 위치·크기·버튼 동작 일치 |
| 2. 편집 화면 | 캡처·드래그·영역 표시·기본값·취소·적용 | 미리보기 위치와 실제 위치 일치, 취소·복원·재실행 유지 |
| 3. 입력·화면 대응 | 이동한 입력 영역, 터치 취소, 회전·크기 변경, 키보드 병용 | 새 위치만 반응, 버튼 밖 드래그 해제, 동시 사격·점프·이동 |
| 4. 자동조준 안내 | 상태판·화면 밖 안내·가림 표시 | 대상 없음·격파·교체·뒤로 이동·화면 이탈·지형 가림의 표시와 실제 상태 일치 |
| 5. 기기 검사 | iPad 치트 앱부터 iPhone·Mac, 이후 일반 앱 | 전체20종 무기·필살기, 수동/자동 조준, 중단/복귀, 저장·성능 회귀 검사 |

조립이나 입력 코드 변경 전 각 플랫폼의 기본 화면과 같은 전투 조건을 저장한다. 편집·전투 중 파일 쓰기0회, 적용 때 설정 저장1회인지 센다. 회전 양쪽·iPad 화면비·Mac 창 축소/확대·전체 화면을 검사한다. 프레임 처리시간·메모리는 같은 기기·장면·계측 조건으로 전후 비교한다. 치트 앱 검사 후 일반 앱에서도 배치 적용과 저장 분리를 확인한다.

구현은 develop에서 분기한 `feat/hud-layout-editor`에서 진행할 계획이다.

## 투두에서 함께 확인한 남은 일

- 알람 앱으로 중단된 뒤 복귀하면 소리가 나지 않는 문제.

- 빌드 경고 전수조사와 빌드·실행·설치 스크립트.
- 튜토리얼0-0~0-4, 앱 아이콘 글자 제거, Android 앱·APK.
- 추가 적의 전체 캠페인 난이도·장시간 발열·메모리 검사.
- 표시시간 후속 계측·실물 키보드·무선 반복 검사와 Intel 대응.
