# HeavyMach Android판을 만든 과정

2026년 10월 30일, HeavyMach의 일반 앱과 치트 앱을 Galaxy SM-S731N에서 실행했다. 기존 C++ 전투 코어와 게임 자원을 그대로 빌드하고, Android의 화면·입력·음향·저장 연결을 추가했다. iPhone·iPad·Mac이 사용하는 소스와 프로젝트, 코어, 자원 2,166개 파일은 작업 전후 해시가 같다.

나는 정상 동작하는 Apple판을 Android 작업 때문에 바꾸지 말라고 요구했다. Codex는 `develop`에서 `feat/android-app`을 만들고 새 앱을 `Android/` 아래에 모았다. 일반 앱과 치트 앱 모두 최적화한 debug 서명 APK다.

10월 30일의 코어 경계 조사 커밋부터 일반·치트 앱 구현과 기기 검사 커밋까지는 **1시간 56분 19초**였다. APK 두 개를 처음 만든 뒤 초기 실행 오류, 입력·GPU 복구·음향을 수정하고 USB·Wi-Fi 설치를 검사한 구간이다. 이후 직접 플레이에서 발견한 업그레이드 오류를 같은 날 추가로 고쳤다.

## 개발 범위를 정한 네 가지 판단

Android 개발이 빠르게 진행된 데에는 Apple판에서 완성한 게임 코드와 자원이 있었다. 나는 이를 재사용하되 정상 동작하는 Apple판을 바꾸지 않고 Android 앱을 만드는 데 집중하도록 요구했다. 플랫폼별 차이와 검사 절차도 구현 전에 정리했다.

### 게임 코어부터 공유한 모듈화

메뉴와 HUD까지 전부 공용 모듈로 분리된 상태는 아니었다. 그래도 전투·탄도·데미지·성장·적 이동·스폰·자동조준은 기존 C++ 코어에 있었다. Android는 이 코드를 NDK로 컴파일했고 같은 이미지·음원·맵·무기 데이터를 사용했다. 복잡한 게임 규칙을 다시 작성하고 수치를 맞추는 작업이 줄었다.

별도로 옮긴 메뉴·HUD·호스트에는 플랫폼 간 대조가 계속 필요하다. 이번 업그레이드 오류도 기존 시작 순서를 옮긴 호스트에서 발생했다. 공유 코어를 그대로 쓰는 부분과 따로 유지하는 부분의 차이가 실제 수정 과정에서 드러났다.

### Apple판을 바꾸지 않는 작업 범위

나는 Android를 만든다는 이유로 정상 동작하는 iOS 프로젝트와 공용 코어를 고치지 말라고 지시했다. Codex는 새 구현을 `Android/`에 두고 기존 파일 2,166개의 해시를 고정해 대조했다. 기존 Apple 파일을 바꾸지 않고 APK를 만들었고, 업그레이드 오류도 Android 호스트 안에서 수정했다.

이 범위 지정은 플랫폼 추가와 공용 구조 재설계를 한꺼번에 진행하는 일을 막았다. Android에서 필요한 연결과 오류에 작업을 집중할 수 있었다.

### 그래픽 컨텍스트와 생명주기 차이의 사전 확인

나는 Android에서 그래픽 컨텍스트가 사라질 수 있고, 백그라운드·포어그라운드 처리도 iOS와 다르다는 점을 미리 확인하도록 요구했다. Codex는 Surface와 EGL 자원을 다시 만들면서 게임 세션을 유지하는 경로를 구현했다. 홈 이동·음향 포커스 상실 시 정지하고, 복귀 뒤 직접 재개하는 절차도 연결했다.

컨텍스트 재생성 검사에서는 개별 FBO 삭제 경로에서 에뮬레이터 드라이버가 종료되는 문제가 나왔다. 해당 경로를 수정한 뒤 에뮬레이터와 Galaxy에서 GPU 복구를 검사했다. Clock 타이머가 음향 포커스를 가져간 뒤의 정지·음향 복귀·재발사도 확인했다. 사전에 짚은 위험이 구현 항목과 재현 검사로 이어졌다.

### 구현 전에 만든 Android 작업 스킬

Android 이식 스킬에는 읽을 코드와 문서, Apple 파일 보존 조건, 빌드와 검사의 순서를 정리했다. 구현 중에는 USB·Wi-Fi 기기 선택, 저장을 유지하는 재설치, 실행·로그 수집·종료·홈 복귀를 기기 실행 스킬과 도구로 추가했다.

무선 ADB 연결 오류의 확인 순서와 이번 업그레이드 회귀 검사도 같은 스킬에 남겼다. 다음 작업에서는 연결과 검사 방법을 다시 찾는 대신 이 명령과 실패 기록에서 시작할 수 있다. [이식 스킬](../../.agents/skills/port-heavymach-android/SKILL.md), [기기 실행 스킬](../../.agents/skills/debug-heavymach-android/SKILL.md)

이번 사례에서는 이미 구현된 게임 규칙을 재사용하고, 변경 범위를 Android로 정하고, 플랫폼 차이를 구현·검사에 반영한 것이 개발 효율에 도움이 됐다. 항목별 시간 절감량은 별도로 측정하지 않았다.

## 무엇을 공유했나

게임 규칙은 Android용으로 다시 작성하지 않았다. 같은 C++ 소스를 NDK로 컴파일해 Android의 `libheavymach.so`에 링크한다. Apple 앱은 기존 Xcode 모듈로 같은 소스를 컴파일한다. 바이너리는 각 OS용으로 따로 만들어진다.

| 공유한 부분 | 위치와 역할 |
|---|---|
| 전투·탄도·데미지 | `Sources/Core/Combat.cpp`, `Player.cpp`, `GameSession.cpp`. 무기 값·발사·피격·플레이어 상태 |
| 이동·적·스폰·소멸 | `Motion.cpp`, `Enemy.cpp`, `World.cpp`, `GameSession.cpp` |
| 자동조준 | `AutoAim.hpp`와 `GameSession.cpp`. 표적 선택·포신 각도·자동조준 상태 |
| 추가 유닛 | `VTOL.cpp`, `Fighters.cpp`, `GroundAA.cpp`. 기체·지상 유닛의 수치·무장·배치 |
| 성장·저장 형식 | `GlobalInfo.cpp`, `SaveData.cpp`. 경험치·레벨·강화·3개 슬롯의 바이트 형식 |
| 화면·입력 계산 | `CanvasGeometry.hpp`, `HUDConfiguration.hpp`, `KeyboardInput.hpp`, `TiltState.hpp` |
| 버튼 상태 | `Sources/iOS/HMButtonState.hpp`. 경로는 iOS지만 내용은 플랫폼 API 없는 C++ 상태 계산 |
| 이미지·음원·맵·무기 데이터 | `Resources`와 `Art/Extensions`. 800개 자원과 manifest를 APK 안에 포함 |
| 외부 라이브러리 | 기존 `vendor/openal-soft`, `vendor/stb` 소스. Android 설정으로 빌드 |

일반 앱은 `HeavyMachCore`, 치트 앱은 `HeavyMachValidationCore`를 링크한다. 일반 APK에는 치트 명령 수신기가 들어가지 않는다. [Android CMake](../../Android/cmake/CMakeLists.txt), [자원 준비 코드](../../Android/tools/prepare_assets.py)

## Android에서 따로 만든 부분

| 파일 | 역할 |
|---|---|
| `GameActivity.kt` | Android 화면, 터치·키보드·가속도 센서, 오디오 포커스, 전체 화면과 생명주기 |
| `GameEngine.kt` | 전용 실행 스레드에서 입력·렌더·수명주기 명령을 순서대로 처리 |
| `Native.kt`, `Bridge.cpp` | Kotlin과 C++의 JNI 연결 |
| `Runtime.cpp` | 코어와 화면을 연결하는 프레임 처리, 메뉴 이동, 저장 이벤트, HUD 편집 |
| `HUD.hpp`, `Menus.hpp` | 기존 Apple HUD·메뉴의 좌표·그리기·입력 순서를 C++로 옮긴 Android 구현 |
| `Media.cpp` | EGL·OpenGL ES 1.1, 텍스처 준비, 전체 화면 출력, 컨텍스트 재생성 |
| `Audio.cpp` | 기존 음원과 OpenAL을 Android OpenSL 출력에 연결 |
| Gradle·Manifest·`Android/tools/` | APK 두 종류, 자원 패키징, USB·Wi-Fi 설치와 자동 검사 |

HUD와 메뉴는 Apple 구현을 참고해 옮긴 별도 소스다. 이후 한쪽의 메뉴나 호스트 로직을 바꾸면 다른 쪽에 반영할 변경인지 대조해야 한다. 전투 코어·원본 자원은 두 플랫폼이 같은 파일을 읽는다.

Android에서 Surface가 사라지면 EGL 자원을 해제하고, 새 Surface에서 GPU 자원을 다시 만든다. 게임 세션과 CPU의 이미지 자료는 유지한다. 홈 이동·잠금·오디오 포커스 상실 시 입력을 해제하고 전투를 멈춘다. 음향 포커스가 돌아온 뒤 게임 재개는 플레이어가 선택한다.

## 직접 플레이에서 발견한 업그레이드 오류

나는 첫 보스를 깬 뒤 2-1에 들어갔을 때 업그레이드 창이 뜨면서도 게임이 계속되는 것을 발견했다. 강화 선택과 확인 버튼을 눌러도 창은 닫히지 않았다.

Codex가 Galaxy 앱을 종료하고 저장 파일을 확보했다. 두 번째 슬롯에는 2-1, 표시 레벨 4, 누적 경험치 2,415가 저장돼 있었다. 이 게임은 경험치를 처리할 때 한 번에 한 레벨씩 올린다. 미션 시작 때 남은 경험치를 확인하면서 레벨 5와 업그레이드 창이 열렸다.

코어는 업그레이드 창을 열 때 전투를 멈췄지만 Android 화면 시작 코드가 직후 `setPaused(false)`를 호출했다. 이 순서는 기존 Apple 호스트에서 옮겨온 것이었다. 전투는 다시 진행됐고, 강화 버튼은 전투 중 입력을 거부하는 조건에 걸렸다. 같은 저장 복사본에서 창이 열린 채 게임 시간이 1.933초에서 3.017초로 늘고 체력이 256에서 235로 줄었다.

![수정 전 업그레이드 창과 진행 중인 전투](media/android-20261030/upgrade-before.png)

Android 호스트에서 업그레이드가 진행 중이면 미션 시작 후에도 정지를 유지하도록 바꿨다. Resume으로 이 정지를 건너뛰지 못하게 했고, 확인은 강화 선택 단계에서 한 번만 처리한다. 창이 닫히는 도중 앱이 중단되면 닫힘 완료 후에도 전투를 멈추고 재개 메뉴를 표시한다. 경험치 공식·레벨 기준·공용 코어·Apple 코드는 변경하지 않았다.

![수정 후 업그레이드 선택 중 정지한 전투](media/android-20261030/upgrade-fixed.png)

에뮬레이터와 Galaxy에서 각각 12개 검사를 통과했다. 실제 터치로 이동 강화를 선택하고 OK를 누르면 이동 등급이 1에서 2로 한 번 증가하고 창이 닫힌 뒤 전투가 재개됐다. 앱 중단·복귀, 전투 중 새 레벨 상승, 닫힘 중 음향 포커스 상실도 검사했다. 일반·치트 APK를 Galaxy에 다시 설치했고 일반 앱의 저장 파일은 설치 전과 바이트가 같았다.

![이동 강화 확인 뒤 다시 시작된 전투](media/android-20261030/upgrade-confirmed.png)

앞선 검사는 35개 스테이지 진입과 무기·입력·생명주기를 확인했다. 이번 실패를 계기로 **남은 경험치가 있는 저장에서 새 미션에 진입하는 검사**를 추가했다. [회귀 검사](../../Android/tools/validate_upgrade.py), [수정 전후 결과](../evidence/android-upgrade-fix-20261030.json)
