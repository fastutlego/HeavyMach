# HeavyMach 개발 과정

대학생 때 플레이한 HeavyMach를 현재의 아이폰에서 다시 실행하고 싶어 이 프로젝트를 시작했다. 이 게임은 내가 2017년 7월 개발자로 전업하는 데 약 35%의 영향을 줬다고 생각한다. 2026년에는 원작의 동작을 분석하고 소스코드부터 다시 구현하도록 Codex에 지시했다. [개발자의 변](../RESTORATION.md)

복원에 사용한 원본은 [Internet Archive의 HeavyMach 1.13](https://archive.org/details/Heavy_Mach_1.13_ios_2.1)이다. 그곳에서 받은 실행 파일과 이미지·사운드·게임 데이터를 분석하고, 원작을 실행한 결과와 새 구현을 대조했다. [원본 출처와 해시](../source-provenance.md)

## 게임 규칙을 소스로 옮기기

Codex는 먼저 함수·문자열·데이터 목록을 만들고 이동·무기·적·진행·화면·음향 책임을 나눴다. REA와 Ghidra로 얻은 의사 코드를 어셈블리와 대조했다. 의사 코드에서 생략된 인수, 구조체 반환, Objective-C 타입 정보는 ARM 호출 규약과 원시 메타데이터를 확인했다.

Codex는 게임 규칙을 C++20으로 구현했다. 화면·입력·음향과 운영체제 연결은 Objective-C++에 작성했다. 현재도 이 구성을 사용한다. 무기·기체·부품·맵 reader를 먼저 만들고, 이동·충돌·탄환·피해·경험치·진행·저장, 메뉴·HUD 순으로 실제 데이터에 연결했다.

수치가 같아 보여도 연산 순서가 다르면 결과가 달라졌다. 피해 강화는 `D + (D / 8) * G`의 정수 나눗셈 순서를 유지했다. Attack의 1.5배는 부동소수 계산 뒤 절삭하고, Defense는 정수 절반을 적용했다. 경험치는 정수 포화·32비트 wrap·한 호출당 최대 한 레벨 상승을 확인했다. 부동소수 연산에는 중간 반올림과 `-ffp-contract=off`를 적용했다.

## 비교한 순서

Codex는 다음 순서로 코드와 실행 결과를 대조했다. 나는 설치된 앱을 직접 플레이하고 차이가 보이는 조건을 전달했다.

1. **정의와 계산:** 같은 무기·기체·맵 값과 경계 입력으로 계산을 비교했다. 데이터 reader와 피해·성장 식이 여기서 결정됐다.
2. **같은 게임 상태:** 위치·무기·강화·난수 조건을 맞춰 이동·사격·적 AI·아이템·카메라를 비교했다. 화면 밖 객체와 draw 호출의 난수 소비도 확인했다.
3. **이벤트와 저장:** World 이벤트가 HUD tick보다 먼저 전달되는지, 레벨업·재장전·메뉴 복귀와 저장이 같은 순서로 발생하는지 확인했다.
4. **실제 앱 경로:** 터치·센서부터 `HMGameView`, 게임 코어, HUD와 OpenGL 출력까지 연결해 검사했다. 코어 통과 뒤에도 입력 변환과 자원 로드 오류를 따로 수정했다.
5. **성능:** 렌더링·음향·파일 쓰기·타이머·화면 제출을 분리해 계측했다. 내가 보고한 프레임 드랍과 지연의 원인을 한 항목씩 대조했다.
6. **플레이:** 치트 앱으로 전체 무기와 미션 조건을 반복 검사하고 일반 앱을 설치했다. 나는 전체 미션을 플레이했고 크래시·오동작·적 이동 이상은 보이지 않았다.

## 초기 구현에서 다시 고친 부분

초기 Codex 구현은 게임의 결과를 재현하는 과정에서 실행 방식까지 바꿨다. 메모리 변경마다 파일을 쓰고, CPU에서 이미지를 만들고, 효과음을 높은 비용의 호출로 재시작했다. 시간 누적 계산은 한 표시 프레임에서 게임이 진행되는 횟수도 바꿨다.

나는 정상적으로 플레이한 기준과 차이를 직접 비교하라고 지시했다. “왜 별도로 설계했냐”, “시간 누적 계산 로직이 들어간 이유는?”이라고 물으며 구현 차이를 확인했다. Codex는 저장 이벤트를 분리하고 OpenGL·OpenAL 자원을 재사용했으며 한 표시 호출에 한 번 갱신하도록 수정했다. [문제와 수정 결과](troubleshooting.md)

## 화면을 넓힌 뒤의 수정

나는 에셋 확대 대신 더 넓은 월드를 보여달라고 요구했다. Codex는 캔버스를 확장한 뒤 좌우 터치, 필살기 낙하 좌표, 보스 활성, HUD와 결과 그림을 함께 검사했다. 메뉴에는 기존 중앙 그림과 연결되는 좌우 배경을 추가했다. 내가 발견한 연결선·검은줄을 Codex가 수정하고 도어 전환도 전체 화면에 맞췄다.

그림을 채우는 일과 게임 좌표를 넓히는 일에는 서로 다른 코드가 필요했다. Codex는 적이 새로 보이는 시점이 전투 시작 시점까지 앞당기는지 확인했고, 미션3-5 항공기형 보스의 동작을 수정했다.

## 공용 모듈과 iPad·Mac

나는 Apple 플랫폼을 하나의 workspace에서 관리하고 공용 코드·자원을 모듈로 만들도록 지시했다. Codex는 iOS 앱을 iPhone·iPad 기기군으로 확장하고 Mac은 AppKit으로 작성했다. 키보드에는 이동·점프·사격·포신 조절·무기 선택·메뉴를 모두 연결했다.

Codex의 Mac 검사는 표시 대기와 시스템 연결 누수 때문에 지연됐다. 계측 기록과 시스템 로그에는 개발 팀 정보가 없는 ad-hoc 서명 때문에 앱 등록이 거절되고 연결을 재시도한 흔적이 남았다. 개발 서명으로 바꾼 일반·치트 앱의 누수는 0건이었다. 표시 경로 수정 뒤 Mac 33개 검사가 통과했다. iPhone·iPad에서는 각각 85개 중 84개가 통과했고 표시시간 기준 실패 한 개가 남았다. [플랫폼별 근거](validation.md)

## 자동조준과 항공기 추가

Codex는 별도 브랜치에서 iPad 치트 앱으로 자동조준을 개발했다. 내 요구는 전방 적 선택·화면 밖 추적·격파 후 전환·탱크 위치에 따른 포신 조정이었다. Codex는 기존 터치 사격과 자동조준을 ON/OFF로 전환하도록 구현하고 전용 발사 버튼을 추가했다.

Codex가 명중률을 높이려고 넣은 C 보정은 탄환의 속도·분산까지 바꿨다. 내가 삭제를 지시했고 Codex가 제거했다. Codex는 자동조준 OFF의 25,200프레임 사격 기록을 추가 전 코드와 비교해 같음을 확인한 뒤 v0.11에 반영했다.

나는 기존 배치를 유지하고 미션별 헬기 평균을 참고해 VTOL을 추가하도록 했다. Codex가 계산한 추가 수량은 113대다. Codex는 배치 코드와 기체를 구현했다. 실물과 달랐던 초기 그림을 다시 그린 뒤 외곽선·크기·불꽃을 수정했다. 다음 F-22·Su-57·MiG-31은 보스전과 직전 구간에 증원으로 추가했다. Codex가 금색 유리·묶음 미사일·화면 밖 진입을 적용했다. 이후 나는 연사 증가를 10%로 줄이도록 했고 Codex가 수치를 수정했다. 이 변경은 v0.12에 들어갔다. [기획과 상세 구현](features.md)

[왜 럭스루나에인가](lux-lunae-intent-20261028.md)에 두 게임의 개인적인 의미, 강한 적을 만든 이유, 텍스트 지시로 확인하려던 것과 실제 제작 결과를 적었다.

REA 작업 목록에는 `inspect_artifact`, `inventory_artifact`, `extract_artifact`, `inspect_plist`, `binary_overview`, `read_binary_inventory_summary`, `list_procedures`, `list_strings`, `search_procedures`, `search_strings`, `analyze_function`, `get_objc_classes`, `get_objc_protocols`, `procedure_pseudo_code`, `procedure_assembly`가 남아 있다. 파일 구조·메타데이터에서 함수별 코드까지 단계별로 조회한 기록이다.

REA 분석은 기하·데이터·저장·이동·플레이어·적·전투·파티클·궤적·아이템·월드·타이틀·메뉴·HUD·화면 전환·카메라·기본 시각 요소·버튼·컨테이너·그래픽 자원·음향·플랫폼·런타임·컴파일러 연결·익명 조각의 25개 함수군으로 분류했다. 분석 목록과 실제 구현의 대응은 [소스 범위](../source-coverage.md)와 [iOS 소스 연결](../ios-source-map.md)에 있다.

구형 도구의 Mach-O 조회 오류는 Ghidra·otool·바이트 파서로 보완했다. `_rea_probe` 심볼 이름 오류, 의사 코드의 구조체 인수 생략, 부동소수·정수 변환 차이는 각각 명령·타입·실행 표본으로 확인했다. 분석기의 외부 thunk 56개는 파일에 본문이 없는 항목으로 분류했다.

## 현재 버전과 다음 작업

v0.9는 내가 정상 플레이를 확인한 기준, v0.10은 공용 모듈·Apple 플랫폼·VTOL, v0.11은 도어·자동조준과 C 삭제, v0.12는 추가 전투기와 진입·연사 수정이다. v0.13은 쉴카·퉁구스카, v0.14는 HUD 편집, v0.15는 아이콘과 일시정지 메뉴 진입, v0.16은 전투기 진입 간격 수정이다. [변경 이력](../../CHANGELOG.md)

GitHub에는 현재 기능·개발 과정과 플레이 자료를 정리했다. 다음 게임 과제는 자동조준 상태 안내·튜토리얼·Android이며, 표시시간·장시간 발열·추가 적 난이도 검사가 남아 있다. [현재 상태](implementation-status.md)
