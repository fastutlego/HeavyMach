# 전체 화면 도어 수정과 v0.10

2026-10-27. Codex가 VTOL 크기·외곽선·불꽃 수정까지 `develop → main`으로 병합하고 main의 병합 커밋 `76cbd21c`에 `v0.10` 태그를 붙였다. 두 브랜치와 태그는 GitHub에 반영했다. 이후 도어 수정은 별도 작업 브랜치에서 진행했다. `v0.10`에는 이번 도어 수정이 포함되지 않는다.

## 수정한 부분

전투 전환의 문이 HUD의 좁은 표시 영역에 잘려 화면 양쪽을 가리지 못했다. 메뉴에서는 원본 문을 중앙·좌·우에 반복해서 그렸고, 높이가 긴 화면에서는 문 전체를 늘였다. 전투 진입 중에는 월드 그림도 생략하고 있었다.

이제 원작의 네 패널로 화면 전체를 덮는 문 하나를 그린다. 중앙의 경고 표지·문양은 원래 크기를 유지하고 바깥 철판 부분을 늘린다. 문 전용 그리기는 HUD의 확대·이동·잘림 설정을 해제한 뒤 실행한다. 문이 열리면 그 뒤의 월드가 보인다.

원본 이미지의 반투명 테두리는 확장 문을 그릴 때 안쪽 픽셀을 읽도록 했다. 문을 닫는 계산이 목표 위치보다 소수점만큼 앞에서 멈춰 남긴 틈도 수정했다. 닫힌 순간의 표시 위치만 맞추며 원작의 이동 계산·화면 교체 시점·효과음 순서는 유지한다. 원본 이미지 파일과 원본480 비교 모드는 바꾸지 않았다.

## 나머지 화면 점검

| 화면 | 확인 결과 |
|---|---|
| 첫 실행·타이틀 | 별도 온보딩 화면은 없다. 타이틀의 중앙 원본과 주변 배경이 화면을 채운다. |
| 슬롯·모드·미션 선택 | 네 화면 비율에서 배경이 가장자리까지 표시됐다. 버튼은 기존 배치와 입력 검사를 통과했다. |
| 화면 전환 | 메뉴·전투 모두 하나의 문이 캔버스 전체를 덮는다. |
| 클리어·게임오버 일러스트 | 기존 전체 캔버스 처리의 회귀 검사를 통과했다. |
| 일시정지·업그레이드·HUD | 월드 위에 겹치는 조작 패널이다. 월드를 전부 가리는 배경으로 늘리지 않는다. |

## 검사 결과

- 닫힌 문: 다섯 화면 크기 × 메뉴·전투, 총10조건에서 배경이 새어 나온 픽셀0개. 소수점 폭694.857도 포함했다.
- 타이틀·슬롯·모드·미션: 네 화면 크기, 총16조건의 배경과 캡처 확인.
- 코어19개 통과. 전환의 화면 교체1회, 닫힘·열림 효과음 순서, 총99tick 유지.
- 관련 iOS 검사19개가 각 최종 실행에서 통과했다. 변경하지 않은16개 결과를 재사용하고 수정한3개를 다시 검사했다. 여기에는 원본 GL 비교13개, 메뉴 입력, 결과 그림, 전환 중 중단·재개가 포함된다.
- 일반·치트 arm64 Simulator 앱과 native Mac 일반 앱 빌드 확인.

새 도어의 실제 iPhone·iPad 설치·화면 검사는 아직 하지 않았다. 폰과 패드에는 앞서 설치한 VTOL 수정본이 남아 있다. Simulator의 화면 검사 결과를 실제 기기의 프레임 성능 측정으로 해석하지 않는다.

일반 앱의 범용 Simulator 빌드는 기존 arm64 OpenAL 라이브러리와 x86_64 링크 요청이 달라 실패했다. arm64 Simulator를 대상으로 지정한 빌드로 확인했다. Intel Simulator 지원은 별도 과제로 남긴다.
