# 쉴카·퉁구스카 추가 연구와 남은 과제

2026-10-28 착수 때 작성한 조사다. 이후 `feat/ground-aa`에서 두 차량의 그림·조립·무장·35개 스테이지 배치를 구현했다. [현재 구현과 게임 화면](ground-aa-art-20261028.md). 릴리스 태그는 v0.12다.

## 개발 가능 여부

**두 지상 유닛의 그림 제작·구현·자체 검증을 Codex가 진행할 수 있다.** 원작의 이동·지형 충돌·파츠 연결·무기·피격·파괴 구조를 사용한다. 원작 데이터의 이동형 지상 유닛 정의 595개 중 25개에는 무기 파츠가 둘 이상 있다. 정의 수에는 같은 차체에 포탑·무장을 바꾼 조합도 포함된다. 실제 미션에 등장하는 종류와 수량은 배치 조사에서 따로 집계한다.

내가 정한 목표는 기존 공중 유닛 6종을 추가했을 때처럼 외형과 파츠는 새로 그리고, 원작의 파츠 조립·이동·무기·효과를 재사용해 기존 적과 비슷하게 동작하도록 만드는 것이다. 쉴카·퉁구스카는 실제 차량의 형태를 유지한다. 이동할 때 차체와 파츠가 털털거리거나 덜컹거리는 묘사도 원작 지상 적과 맞춘다.

## 두 유닛의 구성안

| 유닛 | 제안 무장 | 원작에서 가져올 것 | 새로 필요한 부분 |
|---|---|---|---|
| 쉴카 | 기관포 1종 | 지상 이동 AI, 궤도 애니메이션, 기관포 탄환·발사음·반동·피격·폭발 | 쉴카의 차체 비례, 네 포신과 포탑·레이더 형태, 파츠 연결점 |
| 퉁구스카 | 기관포 + 미사일 2종 | 같은 이동 구조, 무기별 독립 조준·발사, 기존 탄환·미사일·연기·음향 | 퉁구스카의 차체·포탑, 좌우 포와 발사관·레이더 형태, 각 무기의 발사점 |

쉴카는 네 포신이 있는 자주대공포다. 포신 수와 게임의 무기 종류 수는 구분해 기관포 한 계열로 구성한다. [박물관 쉴카 자료](https://www.kskdivniy.ru/museum/eksponaty/zsu-23-4-shilka/)

퉁구스카는 포와 미사일을 함께 사용하는 차량이다. 소련 시기의 2S6 형상을 기본 후보로 삼고, 이후 M1 형상의 부품과 섞이지 않도록 측면 사진을 모아 대조한다. [박물관 퉁구스카 자료](https://www.kskdivniy.ru/museum/eksponaty/tunguska/)

게임에서는 기존 적처럼 플레이어 탱크를 공격한다. 무기 수치·탄도·연사 규칙은 기존 게임 무기를 기준으로 정한다. 후속 지시로 쉴카 흰색 총탄 6발, 퉁구스카 흰색 총탄 4발·미사일 2발로 정했다. HP와 152대 배치는 [구현 문서](../ground-aa-expansion.md)에 기록했다.

## 재사용할 코드와 자원

| 항목 | 확인한 구조 | 적용 방법 |
|---|---|---|
| 이동 | `Enemy.cpp`의 `machType == 0`에서 전진·후진·정지 선택 | 두 차량을 같은 지상 유닛 유형으로 등록 |
| 지면 접촉 | `Motion.cpp`가 지면 선분을 따라 이동하고 인접 선분·경사·낙하를 처리 | 기존 물리 경로 사용, 바퀴 접지 위치에 맞춰 그림과 충돌 범위 설정 |
| 차체·포탑·무기 | `MachPartDefinition`이 부모·자식 파츠와 소켓·그리기 순서를 저장 | 궤도/차체, 포탑, 기관포, 미사일 발사기를 분리해 연결 |
| 여러 무기 | `GameSession.cpp`가 무기 파츠마다 `WeaponState`를 만들고 `tickWeapon` 호출 | 퉁구스카 기관포와 미사일에 각자의 상태·발사점을 부여 |
| 피해·파괴 | 기존 HP·피격음·폭발·아이템·경험치 경로 | 기존 적 처리 그대로 사용 |
| 추가 배치 | `VTOL.cpp`의 별도 추가 정의와 배치 방식 | 원작 배치와 기존 추가 항공기 보존, 두 지상 유닛만 추가 |

기관포 후보는 `E_0505_Wpn`이다. 원작에서 3발 묶음, 묶음 안 간격 0.2초로 정의되어 있다. `E_0506_Wpn`은 4발 묶음이다. 미사일 후보는 `E_ArmoCar_Msl_01` 계열이다. 전체 발사 주기는 묶음 간 대기와 AI의 조준·대기 시간을 합쳐 결정된다. 서로 다른 무장을 연결한 기존 예로 `MBoss0501`이 있다. HP는 배치할 구간의 일반 지상 적을 기준으로 정한다.

`E_Tank_Body_03.png`와 `E_0505_Body.png`는 2프레임 그림이다. 새 차체 그림의 궤도 프레임·색조·질감과 조립 상태를 비교할 참조로 사용한다. 쉴카·퉁구스카의 차체·포탑·포신·발사관·레이더는 모두 새로 그린다. 탄환·연기·폭발·효과음과 파츠 조립 코드는 재사용한다.

## 이동 중 차체와 파츠의 흔들림

이 요구는 외형·무장과 같은 필수 조건이다. 차체 전체를 한 장으로 묶으면 파츠별 움직임과 반동이 사라지므로 기존 파츠 구조를 유지한다.

현재 코드에서 확인한 동작은 다음과 같다.

- **궤도 프레임:** `Visuals.cpp::drawParts`는 지상에서 이전 위치보다 3논리 좌표 단위 넘게 움직일 때 차체 그림의 다음 프레임을 표시한다. 좌우 이동에 같은 거리 조건을 쓴다.
- **차체 기울기:** `Motion.cpp::processLand`는 지면 각도 차이의 0.125만큼 차체 회전을 따라가게 한다. 지면 선분이 바뀔 때 접촉 위치도 갱신한다.
- **무기 반동:** `drawWeapon`은 발사 때 생긴 `fireOffset`을 그리기마다 1/5씩 줄인다. 포와 차체가 서로 다른 움직임을 보이는 기존 경로다.
- **차체 진동:** `useEngineBounce`가 켜진 경우 이동 중 진폭 계수는 0.15, 정지 중은 0.04다. 일반 파츠는 계산값 전체, 무기는 절반을 받는다. 현재 적 생성 경로는 이 옵션을 켜지 않는다. 원작 적의 덜컹거림은 궤도 프레임·지면 회전·반동과 함께 촬영해 대조할 예정이다.

구현에 앞서 기준 지상 적을 평지·경사에서 전진/후진·정지·사격시키고, 차체 중심·포탑 연결점·포신 위치를 프레임별로 비교한다. 그림 프레임 변화, 지면 회전, 발사 반동이 각각 만드는 움직임을 나눈다. 그 결과로 두 차량의 움직임을 맞춘다. 추가 진동이 필요하면 두 유닛에만 적용하고, 기존 적의 움직임은 유지한다.

비교 장면은 원작 지상 적·쉴카·퉁구스카를 같은 지면과 화면 배율로 촬영한다. 이동 중 흔들림의 크기·속도, 멈춘 직후 상태, 경사 연결부의 덜컹거림, 사격 중 포신 반동을 확인한다. 파츠가 떨어져 보이거나 바퀴가 지면에 잠기거나 탄환이 포구 밖에서 생기면 수정한다. 이후 치트 앱에서 두 차량과 원작 Tank를 같은 화면에 놓고 촬영했다. [게임 화면](ground-aa-art-20261028.md).

## 착수 당시 구현 순서와 검사

1. **원작 동작 대조:** 기준 지상 적의 평지·경사·역주행·정지·사격을 촬영하고 파츠 움직임을 기록한다.
2. **그림:** 실차 측면 자료와 원작 파츠를 함께 보고 쉴카·퉁구스카를 그린다. 실제 게임 크기에서 차체·포탑·포신·발사관과 도트 외곽선을 확인한다. [기존 실차 유닛 제작 절차](../../.agents/skills/integrate-game-art/SKILL.md)를 쓴다.
3. **유닛 정의:** 새 파츠·무기 이름을 등록한다. 기존 무기의 수치를 복사하고 새 포구에 연결한다. 무기 파츠마다 발사점을 가지므로 두 무장도 따로 연결할 수 있다. 여러 포신에서 번갈아 발사하는 연출은 현행 단일 포구 구조에 작은 확장이 필요하다.
4. **미션 배치:** 미션별 기존 지상 적 수·HP·무장을 집계해 쉴카는 기관포 적 구간, 퉁구스카는 기관포와 미사일이 등장하는 후속 구간에 추가하는 표를 만든다. 원작 1,182개 적 배치, VTOL 113대, 전투기 증원 72대를 보존한다. 지상 유닛은 지면 높이·구덩이·경사·적 간격을 검사해 위치를 고른다.
5. **치트 검사:** 두 차량의 전진·후진·정지·경사·파괴, 무기 1종/2종 발사, 화면 밖 진입, 일시정지·재개를 확인한다. 플레이어 전체 20무기로 피격·파괴하고 수동/자동조준 모두 검사한다.
6. **성능·설치:** 같은 장면의 추가 전후 프레임·메모리·파일 쓰기를 비교한다. iPhone·iPad Simulator와 Mac 치트 앱을 검사하고, 연결·잠금 해제된 실기기에 일반·치트 앱을 설치해 확인한다.

도안 2장을 제작했다. 코드·자동 검사·Simulator·Mac 검증은 현재 도구로 진행 가능하다. 실기기 설치·직접 검사는 기기 연결과 잠금 해제가 필요하다. 이번 과제에서는 새 유닛 구현과 앱 설치를 시작하지 않았다.
