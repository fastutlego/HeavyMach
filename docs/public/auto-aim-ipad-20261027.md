# 자동조준 iPad 치트 앱

`develop`의 `8fdeb629`에서 `feat/auto-aim-ipad-validation`을 분기했다. 자동조준 개발과 검사는 이 브랜치에서 진행한다. develop·main에는 병합하지 않았다. 2026-10-27 07:33 후속 작업에서 iPhone·iPad의 정식·치트 앱을 모두 업데이트 설치했다.


**표적 표시·버튼 순서 수정**

사용자 지시로 버튼 순서를 A → 표적 전환 화살표 → 사격 조준경으로 바꿨다. 표적 네 모서리에 사선과 상태 표지를 연결했다. LOCKED는 조준 가능, TRACK은 추적 중, BLOCKED는 지형·사거리 등으로 발사할 수 없는 상태다. 표적 획득 때 사선을 0.15초 동안 그리고 표지를 한 번 점등한다. 화면 가장자리에서는 글자를 안쪽에 배치한다. 기존 OpenGL 선 그리기를 사용하며 프레임마다 파일을 쓰거나 이미지를 생성하지 않는다.

![iPad에서 검사한 표적 표시와 버튼 순서](media/auto-aim/lock-label-ipad.png)

왼쪽부터 A, 표적 전환, 사격이다. 실제 iPad GPU의 논리 화면을 캡처했다.

시뮬레이터·실제 iPad·실제 iPhone에서 관련3개씩 통과했다. 버튼 순서와 터치 판정, 상태 표지와 화면 경계,20종 무기 이동·점프·사격·피해를 검사했다. 두 기기에 치트·정식 앱4건을 무선으로 업데이트 설치하고 각각 실행했다. 기존 앱 삭제·저장 초기화는 하지 않았다. 자동조준 UI는 치트 앱에만 제공하며 정식 앱은 기존 터치 조작을 유지한다. develop/main에는 병합하지 않는다. 이전 프레임 기준 실패는 이번 검사 범위에 포함하지 않았다.

**앞선 HUD 통합 검사 — 06:54**

M·C 버튼을 삭제한 수정본을 2026-10-27 06:54에 iPad에 설치했다. A를 켜면 자동조준과 명중 보정이 함께 작동하며 끄면 기존 터치 조준·발사로 돌아간다. 버튼3개는 원본 HUD를 참조한 금속 패널로 바꾸고 하단 오른쪽 레일에 붙였다.

![실제 iPad의 하단 HUD 자동조준 버튼](media/auto-aim/hud-integrated-ipad.png)

이전 배치는 왼쪽부터 A, 사격, 다음 표적이었다. 실제 iPad GL 출력 원본이며 이미지 합성으로 버튼을 붙인 예시가 아니다. 시뮬레이터와 실제 iPad에서 각각4개 검사가 통과했다. HUD 좌표, A 전환 후 수동 발사, 화살표 터치의 표적 전환, 입력 해제와20종 무기 이동·점프·사격을 검사했다. 실제 Device Hub 화면에서도 M·C 삭제와 A 전환에 따른 버튼 표시를 확인했다. 이전 프레임 검사 실패는 남아 있다.

## 조작

| 버튼·키 | 동작 |
| --- | --- |
| A | 자동조준 ON/OFF. OFF이면 기존 터치 조준·발사 |
| 조준경 버튼 / F | 누르는 동안 발사, 떼면 유지 입력 해제 |
| 화살표 버튼 / R | 다음 표적 선택. 다른 후보가 없으면 해제 |

M 버튼을 삭제하고 A 하나로 전환하도록 수정했다. 이동·점프·무기 전환·메뉴는 두 모드에서 사용할 수 있다. 자동 모드에서 빈 월드를 눌러도 조준점이나 발사가 바뀌지 않는다. 가까운 곳을 눌러 대시하는 기존 동작은 유지했다.

모드를 바꾸면 발사 유지 입력을 지운다. F나 화면 발사 버튼을 누르고 있었다면 뗀 뒤 다시 눌러야 한다. 이동 키는 계속 사용할 수 있다. 터치와 F를 함께 사용하면 마지막 발사 입력을 뗄 때 사격을 멈춘다. 이미 나간 탄환과 시작한 연사 묶음은 유지한다.

## 목표와 탄도

살아 있고 탱크 앞에 있는 적 중 가장 가까운 적을 고른다. 선택 후에는 화면 밖으로 나가도 유지한다. 죽거나 사라지거나 탱크 뒤로 넘어가면 다른 적으로 바꾼다. 표적 변경 버튼은 거리 순으로 후보를 순환한다. 후보가 없으면 포신을 표준 각도로 돌린다.

원작의 60Hz 탄환 계산에 맞춰 무기 탄속·중력·수명, 포구 위치, 적의 직전 이동을 계산한다. 이동·점프 중에도 포구 위치를 갱신한다. 낮은 탄도가 지형에 막히면 높은 탄도를 검사한다. 두 경로가 막히거나 수명 안에 닿지 않으면 발사를 시작하지 않는다.

C 버튼을 삭제하고 명중 보정을 자동조준에 포함했다. 자동으로 쏜 탄환은 발사 시 선택한 적을 향하도록 비행 중 속도를 보정한다. 수동으로 새로 쏜 탄환에는 적용하지 않는다. 모드를 바꾸기 전에 이미 발사한 유도 탄환은 기존 보정을 유지한다. 산탄 분산과 상공 폭탄의 가로 생성 위치도 보정한다. 표적 HP는 실제 탄환 충돌 후 기존 피해 공식으로 감소한다. 탄약·재장전·적탄은 원래 규칙을 따른다.

조준 표시는 적의 네 모서리에 그리고 사선과 상태 표지를 연결한다. 추적 중 주황, 조준 가능 시 녹색, 차폐 시 회색이다. 화면 밖 적은 가장자리 화살표로 표시한다. A·사격·다음 표적 버튼은 기존 점프·메뉴·무기 버튼을 참조한 회색 금속 패널과 노란 기호로 바꿨다. 하단 HUD 오른쪽 레일에 붙이고 원래 HUD의 위치·확대 비율과 터치 변환을 함께 사용한다.

## 프레임 계측과 남은 검사

시뮬레이터의 실제 화면 출력 경로를 180프레임씩 측정했다. 프레임 작업 p95는 수동 44.21ms, 탄도 예측 44.84ms, 명중 보정 44.42ms였다. 세 모드 모두 16.67ms 기준에 실패했다. 렌더러는 `Apple Software Renderer`였고 최종 화면 확대·출력에 대부분의 시간이 들었다. 자동조준 추가분은 이 실행에서 각각 0.63ms·0.21ms였다. 이 수치는 실기기 성능으로 사용하지 않는다.

Mac에서 코어 조준 계산 10,000회를 별도로 측정한 p95는 약 0.0055ms였다. 이 역시 iPad 프레임 시간과 구분한다.

최신 iPad의 실제 화면 출력도 각 모드 180프레임씩 측정했다.

| 조건 | 수동 p95 | 탄도 예측 p95 | 명중 보정 p95 |
| --- | --- | --- | --- |
| Device Hub 화면을 연 상태 | 17.13ms | 20.26ms | 17.85ms |
| Device Hub 화면을 닫은 상태 | 26.67ms | 16.81ms | 17.49ms |

모든 값은 대기를 포함한 프레임 함수 실행 시간이다. 두 실행 모두 16.67ms 기준에 실패했다. 화면을 닫은 실행의 평균 호출 간격은 수동 16.81ms, 예측 16.76ms, 보정 16.76ms였다. 기존 렌더러는 화면 출력 뒤 명시적으로 기다린다. 따라서 이 값 전체를 조준 계산 시간이나 GPU 작업 시간으로 해석할 수 없다. 실제 기기에서 프레임 지연이 없다고 판정하지 않았다.

다음 계측에서는 명시적 대기·게임 갱신/조준·GL 작업·실제 표시 간격을 나눠 기록하고 같은 장면으로 비교한다. 이번 설치에서는 렌더러와 검사 기준을 바꾸지 않았다. 이전 서명 실패와 이번 프레임 실패 기록을 보존했다.

병합 전에는 프레임 기준 초과 원인 분리, 실제 미션의 지형·보스 전투, 버튼 검수를 끝낸다. 다른 Apple 기기의 자동조준 조작과 장시간 발열 검사도 남았다. 명중 보정은 사용자 지시에 따라 자동조준에 포함하며 별도 C 옵션을 제공하지 않는다.
