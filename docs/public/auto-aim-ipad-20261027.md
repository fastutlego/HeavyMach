# 자동조준 iPad 치트 앱

`develop`의 `8fdeb629`에서 `feat/auto-aim-ipad-validation`을 분기했다. 자동조준 개발과 검사는 이 브랜치에서 진행한다. develop·main에는 병합하지 않았다. iPhone·iPad의 정식 앱을 교체하지 않았다.

최신 수정본을 2026-10-27 06:26에 실제 iPad에 설치했다. 기능 검사 4개가 통과했다. 화면에서 버튼을 눌러 이동·점프·자동조준 사격도 확인했다. 프레임 시간 검사는 아래와 같이 실패했으며 후속 계측이 남았다.

## 조작

| 버튼·키 | 동작 |
| --- | --- |
| M | 기존 터치 조준·발사. 켜진 M을 누르면 OFF |
| A | 자동조준. 켜진 A를 누르면 OFF |
| 조준경 버튼 / F | 누르는 동안 발사, 떼면 유지 입력 해제 |
| 화살표 버튼 / R | 다음 표적 선택. 다른 후보가 없으면 해제 |
| C | 명중 보정 ON/OFF 비교. 치트 앱 전용 |

M과 A는 동시에 켜지지 않는다. 둘 다 OFF여도 이동·점프·무기 전환·메뉴는 사용할 수 있다. 자동 모드에서 빈 월드를 눌러도 조준점이나 발사가 바뀌지 않는다. 가까운 곳을 눌러 대시하는 기존 동작은 유지했다.

모드를 바꾸면 발사 유지 입력을 지운다. F나 화면 발사 버튼을 누르고 있었다면 뗀 뒤 다시 눌러야 한다. 이동 키는 계속 사용할 수 있다. 터치와 F를 함께 사용하면 마지막 발사 입력을 뗄 때 사격을 멈춘다. 이미 나간 탄환과 시작한 연사 묶음은 유지한다.

## 목표와 탄도

살아 있고 탱크 앞에 있는 적 중 가장 가까운 적을 고른다. 선택 후에는 화면 밖으로 나가도 유지한다. 죽거나 사라지거나 탱크 뒤로 넘어가면 다른 적으로 바꾼다. 표적 변경 버튼은 거리 순으로 후보를 순환한다. 후보가 없으면 포신을 표준 각도로 돌린다.

원작의 60Hz 탄환 계산에 맞춰 무기 탄속·중력·수명, 포구 위치, 적의 직전 이동을 계산한다. 이동·점프 중에도 포구 위치를 갱신한다. 낮은 탄도가 지형에 막히면 높은 탄도를 검사한다. 두 경로가 막히거나 수명 안에 닿지 않으면 발사를 시작하지 않는다.

C를 끄면 발사 후 원래 탄속·분산을 사용한다. C를 켜면 발사 시 선택한 적을 향하도록 비행 중 속도를 보정한다. 산탄 분산과 상공 폭탄의 가로 생성 위치도 보정한다. 표적 HP는 실제 탄환 충돌 후 기존 피해 공식으로 감소한다. 탄약·재장전·적탄은 원래 규칙을 따른다.

조준 표시는 적의 네 모서리에 그린다. 추적 중 주황, 조준 가능 시 녹색, 차폐 시 회색이다. 화면 밖 적은 가장자리 화살표로 표시한다. 버튼 테두리는 원작의 `Btn_Empty.png`를 재사용했다. 최종 기호·배치는 사용자 검수가 남아 있다.

코어의 탄환 검사는 실제 생성·비행·피격 함수를 사용한다. 포신 회전 완료 후의 탄도를 분리해 검사했다. iPad 검사는 실제 포신 회전과 입력 처리를 포함한다. 검사장에서는 Stage01의 시험용 복사본에 평지를 두고, 원래 헬기 AI를 생성했다. 반복 피격 관측을 위해 헬기 HP만 높였다. 정식 미션 데이터 파일은 수정하지 않았다.

위 222/222는 해당 시험장·이동 패턴의 결과다. 모든 미션의 모든 지형에서 명중을 확인했다는 뜻은 아니다. 차폐나 사거리 밖 표적에는 발사를 차단한다.

### 최신 iPad 설치·직접 조작

후속 수정본의 무기 20종 자동조준 이동·점프·피격, 수동 키보드 무기 20종, 이동·점프·발사 해제, 조준 모드 전환 검사가 모두 통과했다. 사격 구간의 저장 호출은 0이었다.

Device Hub의 실제 iPad 화면에서 Stage01을 시작했다. 전진·정지, 부스터 점프, 녹색 표적 표시, 발사 버튼을 누른 뒤 적 소멸과 경험치 증가, 무기 전환과 지원 공격, M/A 전환을 확인했다. 자동조준을 켜고 메뉴에서 일시정지했다. Resume Game을 누르면 이어서 플레이할 수 있다.

## 프레임 계측과 남은 검사

시뮬레이터의 실제 화면 출력 경로를 180프레임씩 측정했다. 프레임 작업 p95는 수동 44.21ms, 탄도 예측 44.84ms, 명중 보정 44.42ms였다. 세 모드 모두 16.67ms 기준에 실패했다. 렌더러는 `Apple Software Renderer`였고 최종 화면 확대·출력에 대부분의 시간이 들었다. 자동조준 추가분은 이 실행에서 각각 0.63ms·0.21ms였다. 이 수치는 실기기 성능으로 사용하지 않는다.

Mac에서 코어 조준 계산 10,000회를 별도로 측정한 p95는 약 0.0055ms였다. 이 역시 iPad 프레임 시간과 구분한다.

최신 iPad의 실제 화면 출력도 각 모드 180프레임씩 측정했다.

| 조건 | 수동 p95 | 탄도 예측 p95 | 명중 보정 p95 |
| --- | --- | --- | --- |
| Device Hub 화면을 연 상태 | 17.13ms | 20.26ms | 17.85ms |
| Device Hub 화면을 닫은 상태 | 26.67ms | 16.81ms | 17.49ms |

모든 값은 대기를 포함한 프레임 함수 실행 시간이다. 두 실행 모두 16.67ms 기준에 실패했다. 화면을 닫은 실행의 평균 호출 간격은 수동 16.81ms, 예측 16.76ms, 보정 16.76ms였다. 기존 렌더러는 화면 출력 뒤 명시적으로 기다린다. 따라서 이 값 전체를 조준 계산 시간이나 GPU 작업 시간으로 해석할 수 없다. 실제 기기에서 프레임 지연이 없다고 판정하지 않았다.

다음 계측에서는 명시적 대기·게임 갱신/조준·GL 작업·실제 표시 간격을 나눠 기록하고 같은 장면으로 비교한다. 이번 설치에서는 렌더러와 검사 기준을 바꾸지 않았다. 이전 서명 실패와 이번 프레임 실패 기록을 보존했다.

병합 전에는 프레임 기준 초과 원인 분리, 실제 미션의 지형·보스 전투, 버튼 검수를 끝낸다. 다른 Apple 기기의 자동조준 조작과 장시간 발열 검사도 남았다. 정식 앱 옵션에 적용하기 전 명중 보정 C의 기본값을 확정한다.
