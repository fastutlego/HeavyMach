# HeavyMach 국문·영문 문서 조사와 구현 계획

2026-10-29. 조사 기준은 main `268f0684`다. [파일별 목록과 원문 해시](evidence/document-localization-inventory-20261029.json)를 기록했다.

## 결정안

한국어 문서의 기존 주소를 유지하고, 대응 영어판을 같은 저장소에 둔다. README·문서 목차·각 문서의 `한국어 | English` 링크로 이동한다. 영어 문서에서 다른 문서를 열어도 영어판으로 이어지게 한다.

기존 `write-project-text`에 영문 번역 전용 스킬, 용어집, 문단별 대조 절차를 연결한다. 국문과 영문 모두 메타카피·불필요한 면책·자기합리화·과장된 표현을 검사한다. 기술 설명과 개발자의 변은 문장 검수 기준을 나눈다. 개인 원고의 인칭·정서·비유·비판은 번역에 보존한다.

문서 파일은 Markdown을 유지한다. 초기 구현에는 번역 서버나 새 문서 사이트를 도입하지 않는다. 기존 통합 보고 사이트에는 같은 원고에서 만든 보고서를 추가한다.

## 현재 규모와 구현에 걸리는 부분

| 대상 | 파일 수 | 한글 포함 파일 |
|---|---:|---:|
| `docs/` 문서·문서성 TXT | 164 | 149 |
| 프로젝트 스킬·정책 | 16 | 13 |
| 복사해 둔 upstream 스킬 원문 | 12 | 12 |
| 루트·Compatibility·Art·Tests 등 | 16 | 15 |
| 외부 라이브러리 README | 1 | 0 |
| 합계 | 209 | 189 |

Markdown은 202개다. 문서성 TXT 등을 합친 209개는 약 135만 문자다. 한글 포함 여부는 번역 후보를 찾기 위한 문자 검사 결과다. 영문만 있는 파일과 기계 출력은 내용 검토 후 공용 원문으로 연결한다. 이번 계획 문서처럼 조사 이후 추가되는 문서도 구현 시 목록에 포함한다.

현재 코드에서 확인한 변경 지점은 다음과 같다.

- `tools/check_publication.py`는 22개 지정 문서의 링크와 145개 원고의 알려진 국문 재발 표현을 검사한다. 영문 전체 검사와 문장 의미 대조는 없다. 코드 블록 처리는 일부 정규식에 의존한다.
- README의 배지와 동기 제목 위치를 문단 번호로 검사한다. 언어 선택 줄을 끼우면 기존 검사가 실패한다. 언어 링크를 별도 요소로 인식하고 저자 본문 검사는 유지하도록 고친다.
- 개발자의 변·럭스루나에 원고와 보존 원문에는 해시 검사가 있다. 언어 링크를 추가할 때 본문을 구분해서 비교하고, 본문 차이가 없는 경우에만 변경 근거와 함께 기준을 갱신한다.
- `tools/document_contract.py`와 `docs/document-map.json`은 현행 읽기 경로와 파일 연결을 관리한다. 여기에 번역 업무와 국·영문 대응 목록을 연결한다.
- `tools/build_report_site.py`에는 국문 제목에 대응하는 절 ID와 문서별 HTML 경로가 있다. 영어 제목으로 바꾼 뒤에도 기존 앵커를 유지할 수 있도록 문서·절 ID를 언어와 분리한다.
- `tools/release.py`는 태그의 CHANGELOG를 읽고 링크를 그 태그에 고정한다. 영어 CHANGELOG도 태그에 포함하고, 릴리스 본문에는 그 버전의 영어 변경 이력 링크를 추가한다.

파일·코드 구조 조사는 마쳤다. 전체 문서의 국문 교정과 영문 번역은 후속 작업이다.

## 모든 문서의 영어 접근 경로

| 원문 | 영어판 경로안 |
|---|---|
| `README.md` | `README.en.md` |
| `CHANGELOG.md`, `CONTRIBUTING.md` 등 루트 문서 | `CHANGELOG.en.md`, `CONTRIBUTING.en.md` |
| `docs/README.md` | `docs/en/README.md` |
| `docs/public/features.md` | `docs/en/public/features.md` |
| `docs/coordinate-policy.md` | `docs/en/coordinate-policy.md` |
| `docs/RESTORATION.md` | `docs/en/RESTORATION.md` |
| `Compatibility/`, `Art/`, `Tests/`, `.agents/` 문서 | `docs/en/repository/` 아래의 대응 경로 |
| 보존한 사용자 원문·과거 인계·외부 스킬 사본 | 원본 경로 유지 + 목록에서 별도 영어판 연결 |
| 이미 영어인 문서·라이선스·명령 출력 | 영어 목차에서 공용 원문 연결 |

영어 목차는 소개·설치·조작·기능·구조·트러블슈팅·개발 과정·개발자의 변·계획과 TODO·검사 기록·과거 자료·작업 지침을 모두 찾을 수 있게 구성한다. 원문과 영어 경로는 목록 파일에서 일대일로 관리한다. 이미 영어인 문서도 목록에서 빠뜨리지 않는다.

일반 문서에는 제목 아래 언어 링크를 둔다. README는 제목→언어 링크→기술 배지→현재 본문 순서로 구성한다. 보존 원문은 파일 자체에 링크를 삽입하지 않고 해당 자료의 목차에서 국문·영문을 연결한다.

문서 안의 링크는 번역 대상 문서의 영어판으로 바꾼다. 소스코드·이미지·영상·원시 로그 링크는 실제 공용 파일을 가리킨다. 번역이 끝나지 않은 문서를 영어판으로 연결하거나 한국어 본문을 영어 파일에 복사해 채우지 않는다. 부분 작업은 브랜치에 모으고, 해당 문서 묶음의 링크가 완성된 뒤 공개한다.

제목 번역으로 GitHub의 자동 절 주소가 달라진다. 기존 국문 절 링크를 유지하면서 새 공통 절 ID를 추가하거나, 목록의 절 대응표로 영어 앵커를 바꾼다. 중복 제목·표·접힌 내용·HTML 링크·이미지 대체 텍스트까지 검사한다. 국기 대신 언어 이름을 표시한다.

## 국문 교정과 영문 번역의 기준

### 기술 설명

한 문장에 동작·원인·결과를 필요한 만큼 담는다. 작업자의 노력이나 정당성을 설명하는 문장은 덜어낸다. 원문에 원인 근거가 없으면 번역에서 인과관계를 추가하지 않는다. 실제 실패 조건·지원 범위·재현 환경은 구체적인 정보로 유지한다.

수정 방향의 예시는 다음과 같다. 왼쪽은 검수용 예문이며 게시할 문구가 아니다.

| 검수용 예문 | 수정 방향 |
|---|---|
| 이 기능은 원작을 존중하기 위한 신중한 접근의 결과다. | 실제 변경을 쓴다. 예: 기존 무기의 탄도와 속도를 유지했다. |
| It is important to note that this ensures a seamless experience. | 실제 동작을 쓴다. 예: The game pauses when the app enters the background. |
| This should not be interpreted as a guarantee of performance. | 측정 환경·대상·수치를 쓴다. 주장 범위를 방어하는 문장을 붙이지 않는다. |
| Codex responsibly addressed the issue. | 발견한 결함과 수정 내용을 쓴다. 예: Codex moved save writes out of the firing path. |

`not`, `only`, `must` 같은 단어를 일괄 금지하지 않는다. 지원하지 않는 플랫폼, 입력 조건, 실제 오류를 설명하는 문장에도 필요한 단어다. 문장의 역할과 문맥으로 판단한다.

### 개발자의 변·인터뷰·회고

‘나’는 작성자이고 Codex는 구현·분석·검사를 수행한 주체다. 영어에서도 두 주체를 구분한다. 과거 경험은 과거 시제로, 현재 동작은 현재 시제로, 계획은 미래의 일로 옮긴다. 비유·감정·비판의 강도를 줄이거나 외부 독자를 위한 변명을 덧붙이지 않는다.

작성자가 GitHub에서 직접 고친 문장은 최신 main과 대조한다. 원고의 사실·표현을 자동으로 재작성하지 않는다. 보존된 대화·인용·스킬 원본은 원문을 유지하고 영어 번역을 별도 파일에 둔다.

### 용어와 수치

용어집에는 `자동조준 → auto-aim`, `연사속도 → rate of fire`, `미사일 이동 속도 → missile speed`, `탄도 분산 → projectile spread`, `포신 고저각 → gun elevation`, `포탑 → turret`, `차체 → hull`을 문맥과 함께 기록한다. ‘자동전투’를 실제 기능 확인 없이 `auto-fire`로 바꾸지 않는다.

럭스루나에의 연사10% 증가와 미사일 속도25% 증가, 체력1.7배처럼 서로 다른 값을 별도 항목으로 대조한다. 삭제된 명중 보정 C 기능을 현행 자동조준 기능으로 설명하지 않도록 완료·삭제·과거 기록을 확인한다. 단위·소수점·플랫폼·명령·키 이름·버전·코드 식별자를 비교한다.

| Vale 시험 설정 또는 기존 검사기의 영문 규칙 | 반복되는 군더더기·용어 불일치 후보 탐지 |
| `docs/document-map.json`·문서 CI | 번역 작업의 읽기 경로와 검사를 기존 업무 체계에 연결 |

원문 해시가 바뀌면 대응 번역을 `stale`로 표시한다. 검토한 원문과 영어판의 해시를 함께 기록하고, 해시만 갱신해서 완료로 바꾸는 명령은 만들지 않는다. 문단 수가 같아도 뜻이 다를 수 있으므로 절·문단 대응과 의미 검토 결과를 함께 남긴다. 한 문장을 자연스러운 영어 두 문장으로 나누는 경우는 허용한다.

자동 검사는 다음 결함을 재현해서 확인한다.

1. 새 국문 파일이 목록이나 영어 목차에서 빠짐.
2. 국문 수정 뒤 영어판이 갱신되지 않음.
3. 영어 설치 링크가 한국어 설치 문서로 돌아감.
4. 제목 번역 뒤 절 링크가 끊김.
5. 표 한 행·그림 캡션·접힌 문단이 번역에서 빠짐.
6. 연사10%와 미사일 속도25%가 뒤바뀌거나 실패가 통과로 바뀜.
7. 코드·명령·파일명·키 매핑이 번역 중 바뀜.
8. 언어 링크 추가로 원고 보호 검사가 깨지거나 본문 변경을 놓침.
9. 금지 문체 예문을 담은 검수 자료·코드·인용을 일반 본문으로 오탐함.
10. 영어 목차에 링크는 있지만 원문을 복사한 한국어 파일이 들어 있음.

수치 교환이나 실패/통과 역전은 단순 숫자 집합 비교로는 찾지 못한다. 표의 열·행 관계와 문장 의미를 별도 대조한다. 테스트도 그 차이를 구분해서 작성한다.

## 작업 순서와 완료 조건

| 순서 | 작업 | 확인할 결과 |
|---|---|---|
| 1 | 원문 목록·해시·문서 종류 확정, 번역 스킬과 용어집 작성 | 209개 기준 목록과 이후 추가 파일에 처리 경로가 있음 |
| 2 | 번역 목록·언어 링크·앵커·원고 보존 검사 구현 | 누락·갱신·링크 오류를 넣은 검사 사례가 실패하고 정상 예제가 통과함 |
| 3 | README, 설치 안내, 트러블슈팅, 회고의 대표 절로 시험 | 기술 설명·표·명령·개인 문체의 번역 방식을 각각 확인함 |
| 4 | 국문 문체 점검과 문서 전체 영어판 작성 | 각 문서에 대응 영어판 또는 이미 영어인 공용 원문이 연결됨 |
| 5 | 문서별 의미 대조와 영어 단독 읽기 | 누락·추가 주장·어조 변경·수치 오류를 수정함 |
| 6 | GitHub 렌더·모바일 폭·언어 이동·이미지·명령 검사 | README→영어 설치→영어 기능→같은 국문 문서 경로가 동작함 |
| 7 | 최신 main 직접 수정 확인 후 develop→main 병합 | 저자 원고·기존 URL 유지, 번역 목록과 CI 통과 |
| 8 | 기존 보고 사이트·SaaS 집필 안내 연결 | 같은 문서와 영어판을 후속 세션에서 찾을 수 있음 |

전체 작업의 완료 기준은 문서 목록 전부의 번역·공용 원문·기계 자료 접근 경로와 검토 결과다. 내부 계획·과거 인계·보존 원문도 목록과 영어 목차에서 접근하게 한다. 이번 요청의 결과는 조사와 구현 계획이며 전체 번역 착수 전 단계다.

## 공개와 후속 갱신

한국어 기본 README는 유지한다. 영어판은 제목 아래 링크로 접근한다. 번역된 설치·기능·개발 과정에서 원문과 같은 화면·영상 파일을 사용한다. 한국어가 이미지에 들어 있는 도표는 편집 가능한 원본에서 별도 영어 그림을 만들고, 실제 게임 캡처는 영문 캡션을 제공한다.

GitHub Releases는 같은 버전에 중복 Release를 만들지 않고 한국어·영어 변경 이력 링크를 제공한다. 이전 태그는 유지한다. 새 영어 문서는 이후 태그의 소스 압축본에 포함된다. 기존 태그에 없는 영어 문서를 해당 태그의 경로로 연결하지 않는다.

SaaS 담당 세션이 읽는 `docs/public/publication-inventory.md`에 영어 문서 목차와 원문 대응 목록을 연결한다. Apps·Mags의 원고 작성과 배포는 그 세션에서 진행한다. 통합 보고 사이트에는 영문 문서 작업의 계획·결과를 기존 목차에 추가한다.
