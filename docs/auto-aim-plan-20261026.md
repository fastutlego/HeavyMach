# 자동조준 개발 계획

2026-10-26 요청을 정리했고, 2026-10-27부터 `feat/auto-aim-ipad-validation`에서 구현·검증한다. 분기 기준은 develop `8fdeb629`다. 완성 전 미병합 지시 이후 사용자가 릴리스를 요청해 develop→main 병합과 v0.11 태그를 완료했다. [현재 구현과 검사](public/auto-aim-ipad-20261027.md)를 따른다. iPhone·iPad·Mac은 같은 코어 계산을 사용하고 입력과 버튼 배치만 플랫폼에 맞춘다.

## 목표 선택

대상은 살아 있고 플레이어 탱크 앞쪽에 있는 적이다. 화면 안에 있는지는 선택 조건으로 쓰지 않는다. 첫 선택은 월드 좌표 거리의 제곱이 가장 작은 적으로 정하고, 거리가 같으면 고정 ID 순서를 사용한다. 선택한 적이 살아 있고 앞쪽에 있으면 더 가까운 적이 나타나도 유지한다.

적이 죽거나 사라지거나 플레이어 뒤로 넘어가면 해제하고 가장 가까운 유효한 적을 선택한다. 현재 게임에서 앞은 월드 +X다. 적·플레이어의 월드 X 좌표로 앞뒤를 판정하며 탱크가 후진한다고 앞뒤를 뒤집지 않는다. 화면 밖으로 나가도 유지한다. 스테이지 전환에서는 이전 월드의 ID를 폐기한다. 객체 주소 대신 ID와 생성 세대를 보관해 삭제된 적을 참조하지 않는다.

별도 버튼은 현재 적을 제외하고 다음 유효한 적을 선택한다. 후보가 없으면 현재 적을 해제한다. 이때 같은 적을 다음 프레임에 즉시 다시 잡지 않도록 수동 해제한 적을 기억한다. 다른 적이 생기거나 사용자가 선택 버튼을 다시 누르면 재선택한다. 유효한 적이 없으면 원본의 표준 포신 각도로 돌아간다.

## 포신 각도와 탄도

현재 포구 위치, 차체 회전, 포신 회전, 무기 탄속·중력·발사 지연과 적 이동을 사용한다. 플레이어의 전후 이동과 점프 높이가 바뀌면 포구 위치부터 다시 계산한다. 터치 흉내로 자동조준을 넣으면 근거리 대시와 입력 거절 조건이 섞이므로 코어에 조준 목표 전달 함수를 따로 둔다.

현재 `Combat.cpp`는 매 tick에 탄환의 세로 속도에서 중력 값을 빼고, 속도에 원본 dt를 곱해 위치를 이동한다. 연속시간 포물선만으로 정답을 내지 않는다. 충돌이 없는 단순 구간의 n tick 뒤 위치는 다음과 같다.

```text
x(n) = x0 + n * dt * vx0
y(n) = y0 + dt * (n * vy0 - g * n * (n + 1) / 2)
```

후보 각도를 계산한 뒤 실제 탄환 갱신 순서로 재검사한다. 포신 회전 지연과 발사 대기 시간도 포함한다. 후보 계산은 별도 예측 상태에서 수행하고 실제 게임 난수·적 상태를 진행시키지 않는다. 플레이어와 적의 속도 단위는 코드에서 확인하며 모든 값을 초당 속도로 추정하지 않는다.

계산 결과는 무기·대상·포구 위치·점프 상태가 바뀔 때 갱신한다. 후보 수와 예측 tick 수에 상한을 두고 프레임별 할당과 파일 쓰기를 하지 않는다. 화면 표시만 마지막에 월드→화면 변환을 적용한다.

## 명중 보장과 원본 무기 규칙

2026-10-27 후속 지시로 C 명중 보정을 삭제했다. 표적 선택과 탄도 예측에 따른 포신 조정만 유지한다. 탄환 생성 후 속도·방향·분산·지원 공격 시작점을 덮어쓰거나 비행 중 유도하지 않는다. 무작위 분산과 적의 발사 후 이동 때문에 빗나갈 수 있다. 발사 즉시 피해를 주거나 벽을 통과시키지 않는다.

기존 `targetAt`는 적의 화면 표시 여부를 검사한다. 화면 밖 대상을 유지하는 것과 화면 밖 탄환 충돌은 별도 문제다. 자동조준 탄환의 유효 대상 판정을 추가하되, 이를 위해 전체 적 AI의 활성 범위를 넓히지 않는다.

## 모든 무기와 필살기

실제 `validationWeapons` 목록의 20종을 사용한다. 무기 이름만 보고 유도 기능을 가정하지 않는다. 각 무기의 포신 회전 허용, 발사 지연, 탄속·중력, 분산, 발사 위치와 특수 이동을 표로 추출한다.

특히 `wpnType == 5`의 공중 지원 3종은 포구에서 나가는 탄환과 시작점이 다르다. `wpnType == 7`도 화면 위 이동 후 위치를 바꾸는 규칙이 있다. 이들은 일반 포물선 풀이에 끼워 넣지 않고 기존 생성·이동 함수로 예상 탄착군을 계산한다. 산탄은 중심 탄도와 전체 탄착군을 구분한다.

## 입력 모드와 발사 — 2026-10-27 후속 요구

사용자의 M 버튼 삭제 지시에 따라 A 하나로 자동조준을 켜고 끈다. A를 끄면 기존 터치 조준·발사로 돌아간다. 기본값은 자동조준 OFF다. 후속 사용자 지시로 정식 앱에도 제공한다. 이전 치트 앱의 양쪽 OFF 저장값도 수동 모드로 읽는다.

| 상태 | 전투 화면 터치 | 사격 입력 |
|---|---|---|
| 수동 ON·자동 OFF | 기존 터치 좌표 조준·발사 경로 유지 | 기존 화면 터치, 키보드 조준점과 F키 |
| 수동 OFF·자동 ON | 빈 월드 영역의 터치로 조준점을 덮거나 발사하지 않음 | 별도 HUD 발사 버튼과 기존 F키. 현재 잠금 대상을 향해 발사 |

자동조준은 자동 발사가 아니다. 발사 버튼/F키를 누르는 동안 기존 무기의 연사·탄약·재장전 규칙으로 발사를 요청하고, 떼면 유지 입력을 해제한다. 대상이 없으면 포신은 표준 각도로 돌아간다. 대상 전환 버튼은 사격 버튼과 분리한다. Mac·키보드의 대상 전환 키는 R로 두고 기존 키 재지정 기능에 등록했다.

모드를 바꾸는 입력이 월드 터치로 전달되지 않게 한다. 전환할 때 기존 터치·키의 발사 유지 상태를 해제하고, 이미 눌린 키/손가락은 뗀 뒤 다시 눌러야 새 모드에서 발사한다. 이미 발사된 탄환은 유지한다. 시작된 연사 묶음과 탄약 처리는 기존 규칙을 보존하며 이전 모드의 발사 입력이 다음 묶음을 시작하지 않게 한다. 자동조준 OFF에서는 잠금 표시와 대상 전환 버튼을 숨긴다.

이동·점프·무기 전환·메뉴 입력은 모드와 별도로 처리한다. 기존 `Player::setTap`에 섞인 근거리 대시는 조준·발사 차단 때문에 사라지지 않게 이동 입력으로 분리한다. 자동 모드의 수동 조준키가 잠금 각도를 덮지 않게 하되 메뉴에서 방향키 역할은 유지한다. 일시정지·포커스 상실 때 유지 입력을 해제한다. 모드 설정 저장은 변경 확정 시에만 수행하며 사격·프레임마다 파일을 쓰지 않는다.

검사에는 누른 채 모드 전환, 멀티터치 이동+사격+무기 전환, 키보드/터치 병용, A를 끈 뒤 수동 터치 발사, 재활성화 시 잔류 입력, 기존 근거리 대시를 포함한다. HUD 편집 후에도 발사·대상 전환 버튼의 그림과 판정은 같은 배치 데이터를 사용한다.

아트는 원본 무기·부스터 버튼과 GameUI 이미지를 참조한다. 별도 파생 이미지로 기본·눌림·대상 있음·대상 없음 상태를 만든다. 이미지 생성 도구에는 실제 원본 버튼을 참조 이미지로 제공하고 금속 질감, 외곽선, 명암, 색과 마모 정도를 맞춘다. 실제 크기로 나란히 배치해 검수한다. 기존 에셋을 덮어쓰지 않는다.

후속 HUD 편집 기능과 같은 배치 데이터로 렌더와 터치 판정을 계산한다. 대상 표시는 화면 밖에서도 선택을 유지하되 가장자리에 방향 표시를 둔다. 화면 밖 적을 화면 안으로 옮겨 그리지 않는다.

## 구현과 검사 순서

1. 코어의 적 ID·전방 판정·선택/해제·교체 상태를 구현한다. 사망·후방 이동·화면 밖 이동·스테이지 전환을 검사한다.
2. 실제 탄환 갱신을 사용하는 예측기를 치트 전용으로 연결한다. 20종 × 정지/이동 적 × 지상/점프 × 거리·높이·차폐 조건을 검사한다.
3. 모든 무기의 원래 탄속·분산·중력이 유지되는지 비교한다. 적 이동 예측이 틀린 경우, 사거리 밖, 벽 뒤, 대상 사망을 실패 사유로 남긴다.
4. 채택한 규칙을 게임 기획→수치/입력/렌더 정책→코드에 반영한다. 폰·패드·Mac 버튼과 키를 연결한다.
5. 세 플랫폼에서 이동·점프·사격·무기 전환·대상 전환을 함께 실행한다. 기존 수동 조작과 저장, 원본 난수 소비가 바뀌지 않는지 검사한다.
6. Instruments로 예측 계산의 CPU·할당을 측정하고 비활성화 상태와 비교한다. p95 추가 비용 1ms 이하를 초기 목표로 삼되 측정 전 달성했다고 쓰지 않는다.

## 전용 브랜치의 구현 규칙

- M 버튼은 삭제했다. A를 누르면 자동조준이 켜지고 다시 누르면 수동 터치 조준·발사로 돌아간다. 자동 모드의 조준경 버튼은 발사, 화살표 버튼은 다음 표적이다. C 버튼과 명중 보정 기능·설정 API를 삭제했다.
- 버튼은 원본 점프·무기·메뉴·하단 HUD를 참조한 금속 패널 시트 `Extensions/AutoAimControls.png`를 사용한다. A·다음 표적·사격을 HUD 오른쪽 레일에 붙이고 HUD와 같은 이동·확대 비율로 그린다. 기본/활성 상태는 노란 기호와 안쪽 테두리로 구분한다. 원본 이미지는 수정하지 않는다.
- 조준 표시와 터치 판정은 동일한 캔버스 사각형을 사용한다. 대상 위의 네 모서리 표시는 입력을 받지 않는다. 추적은 주황, 조준 가능은 녹색, 경로 차단은 회색이다. 화면 밖에는 방향 표시를 그린다.
- 낮은 탄도가 지형에 막히면 높은 탄도도 계산한다. 둘 다 막히거나 탄환 수명 안에 도달할 수 없으면 발사를 시작하지 않는다. 이미 시작한 연사 묶음은 원본 탄약·재장전 처리대로 끝낸다.
- 자동조준 탄환은 화면 밖 대상 충돌과 검사 집계를 위해 대상 ID만 보관한다. 원본 난수로 생성한 속도·분산·시작점과 비행 중 중력 운동을 유지한다. 이미 나간 탄환은 모드를 바꿔도 원래 운동을 계속한다.
- 각도 계산은 최대 600 tick의 후보를 검사한다. 예측 중 실제 난수를 소비하지 않는다. 발사 때는 원래 난수 호출을 유지한다. 입력·사격·예측 프레임에서 게임 저장을 쓰지 않는다.
