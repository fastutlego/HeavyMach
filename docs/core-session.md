# Native stage session integration

GameSession connects World, Player, Enemy, Motion, Combat, Visuals and ItemBox into an executable stage loop using the original parsed `.mch`/`.map` records. It requires actual tile dimensions and a caller-owned nonnegative31-bit RNG stream. Tests use a named deterministic stream; production must choose the original random() source. It never alters original resource files or game stats.

Public API: construct with GameData&, SaveSlot&, tileSize callback and random31 callback; start(mode,mission,stage); tick(globalTime,filteredAccelY); touch(logicalPoint,state); booster; selectWeapon/cycleWeapon; upgrade actions; resultButton. Data, slot and callbacks must outlive the session. World/Player accessors expose read-only state. takeEvents transfers owned-string audio/UI/save/unsupported events; the native host distributes them once.

renderItems() is the preferred renderer stream: it preserves interleaved DrawSprite/TrailMesh layer order. sprites() remains a sprite-only compatibility view. Both already contain original logical screen coordinates, +Y upward. Conversion is worldPos-camera+(240,160). The native renderer applies a single Y flip and viewport letterboxing, not another camera transform. Result and upgrade UI are intentionally not emitted as session sprites; HUD consumes World.presentation and Player UI events. World layers are stable-sorted. Each machine draws parts in original local zOrder before moving to the next machine. Sprite transform/atlas/blend contracts are described in core-visuals.md.

The session prelude applies World.moveInput to the already-filtered accelerometer Y, advances World, then traverses enemy list,64 pooled particles, player and append-ordered bullet/item children. Removal is deferred until the next corresponding child traversal. Enemy destruction therefore retains its subsequent sound/gauge effects. Dynamic bullet and item creation appends into the same traversal list. Player passives tick after world objects, including while paused. The native loop must call exactly one tick per original60Hz step.

Machine graphs follow GobHvMach addParts0x4214/0x428c and Enemy decode0x147e8. Parts of type2 get WeaponState, the named weapon or E_Default_Wpn fallback; weapon initialization consumes its original random draw before Enemy's drop draw. Player parts use0x1be84/0x1be0c: body→top socket1→weapon socket1, fixed player bounds and rotation invalidation-.01. Replacing one upgraded part preserves the other weapon state/RNG. Original attachment is a separate graph from the flat machine child list. Base-part center offsets refresh on setChildParts0x11748.

Target containment uses ItemBox's recovered inclusive QobBase point test0x7d78, player bounds[-20,0,20,50] and enemy accumulated bounds0x428c. Enemy bounds accumulate from the BASE part, not the new child. For nil BaseParts, the host uses zero-valued geometry then the original minimum clamps. The armv6 ObjC nil struct-return exact bytes remain unverified; this choice is explicit and no custom circular hitbox is added. Camera containment0x7c78 uses the original right margin540 and vertical320, with per-machine inScreen updated before weapon child ticks. Bullet target traversal retains list order and existing removal flags until the next tick.

Combat event callbacks perform terrain tests, HP damage, EXP, loot, ammo removal, reload gauges, audio and pool-backed impact particles. Ammo replacement is deferred until the active weapon tick returns so no native object is destroyed during its own method. Original selected slot0 gun has unlimited gameplay ammo. Player death configures the original game-over presentation0xbf74 (step1, gameState3, StageClear.jpg, typo1 or survival3), saves state and pauses. NextStage uses World progression and SaveProgress. Result OpenStage opens the next resource synchronously; the following fade resumes gameplay.

Player tick adds safe-backline/trash behavior0x1bd04 with initial values-32000 from0x1bb84. Booster smoke0x1cc70 preserves successful-pool-dependent four RNG draws, scale, rotation, velocity and lifetime. Bullet atlas rules come from GlobalInfo0x10e00: EnemyBullet0*=4×4, EnemyMissile*=2×4, other bullet tiles4×8. Pickup item/weapon atlases are7×4 from0x1c64c. Fixed explosion atlases come from World init0xb0a4 and muzzle/shell splits0x11e64.

Touch coordinates follow original bottom-left480×320. State2 release is delivered even while paused to avoid latched automatic fire after native cancellation, pause or upgrade; press/move remain blocked while paused. This is an explicit modern input-lifecycle fix. UpgradeClose begins a host animation; finishUpgradeSlide must be called only after that slide completes. SaveChanged tells the host to serialize the existing SaveSlot; it does not perform filesystem writes.

BulletVisual and Trail are integrated. Flame/Smoke visual state and RNG update once per collected frame. Trail creation appends before its bullet; trail tick precedes bullet tick, and its mesh is collected before the bullet draw appends a new trail point. Trail append occurs during draw even while paused. Mesh translation is screen-space; vertices are local, UV is normalized to the native PNG full image. Original padded GL texture extents are thus remapped to native UV0..1. The renderer must reject nonfinite triangles from the retained original initial-duplicate-point behavior. Particles register visibility when their tick executes, so effects created afterward by player fire or bullet drawing do not appear until the next particle tick.

SessionEventKind::Unsupported still reports missing enemy part definitions rather than silently substituting art. The nil BaseParts struct-return choice described above, complete QobManager edge-case behavior, camera quake execution, native sound/UI scheduling and device pixel equivalence remain outside the validation claim.

Validation: GameSessionTests loads actual RawData and converted PNG dimensions; Stage01 firing/movement/pause/release/weapon/booster and Stage02 enemy regeneration, plus the original starting RaderLsr weapon producing TrailMesh records, execute under ASan+UBSan with clang C++20, -Wall -Wextra -Werror and -ffp-contract=off. Isolated combat fixtures relocate original enemy definitions near the original player spawn without changing HP/damage/weapon/parts stats: a gun kill yields3EXP; a multiple-enemy fixture damages and kills the player, enters paused gameState3. The pause→release→resume regression asserts no continued weapon sound after the outstanding burst completes. Test fixtures do not affect production resources.
