# 아이폰 프레임 드랍 조사 · 2026-10-24

사용자 추가 확인: 같은 아이폰에서 원본 IPA 호환 실행판은 프레임 드랍이 없었다. 소스 복원판은 주인공 사격·메뉴 애니메이션에서 한 자릿수 FPS로 떨어졌다. 이는 사용자 관측이며 이번 실기기 계측 결과는 아니다.

결론: 복원판의 화면 합성 경로를 최우선 원인 후보로 좁혔다. 현재 렌더링의 60Hz 예산 초과는 기존 실제 UIKit 검사로 확인됐다. 당시 설치본의 한 자릿수 FPS 원인을 단일 함수까지 확정하지는 못했다. 소스 복원판은 ARM 인터프리터를 사용하지 않는다.

## 핸드오버 대조

현재 HEAD 51d859339b9eaa4c0e396c695bb7342e23a6db6c, feat/playable-game-20260908. HeavyMach는 미추적 상태다. 최초 기능 변경 d495d8aa의 부모6935c919 및 복구678266df 객체를 확인했다. 기존 Unity 복구와 dirty 파일을 변경하지 않았다.

복원판의 주요 기능·10맵 치트 검사는 기존 완료 범위다. 실기기 성능과 원본 전체 동등성은 미완료다. 폰 설치본은 핸드오버상13:21 Debug이며 전체Sprite CPU 래스터 도입 전이다. `build/sprite-native-before`는 후속 교체 직전 소스이며13:21 설치본의 완전한 소스 스냅샷으로 보증할 수 없다.

## 확인한 구현 차이

- 호환판: 보존 touchHLE의 `src/frameworks/opengles/gles_guest.rs:790`에서 원본 glDrawArrays를 GLES DrawArrays로 전달한다. 원본의 그래픽 호출 경로를 유지한다.
- 복원판의 이전 경로: HMGameView.drawRect가 뷰포트 확대 후 UIKit 이미지를 개별 합성한다. 메뉴도 같은 경로다. HMMedia는 처음 쓰는 이미지/atlas tile을 동기로 읽고 픽셀 변환한 뒤 캐시한다. 최초 애니메이션 프레임과 첫 사격의 끊김 후보이며 캐시 후 지속 저하까지 설명하는 증거는 없다.
- 이전 음향 경로: 첫 재생 시 AVAudioPlayer를 생성하고 매번 stop/currentTime/play를 호출한다. 게임 tick에서 호출하므로 사격 시 지연 후보다. 최신 코드는31음원 사전 준비와 pause 재시작으로 이미 바뀌었다. 소리가 정상으로 들린다는 사실만으로 호출 지연이 없다고 판단할 수 없다.
- 현재 경로: 모든 sprite를 CPU로 래스터화한 뒤 각 draw마다 행 뒤집기, CFData 복사, CGImage/UIImage 생성과 합성을 수행한다. 마지막에480×320 전체 이미지를 뷰에 확대한다. SpriteRaster/TrailRaster만 -O2이며 HMMedia의 바이트 반복문은 Debug -O0다. 이 현재 경로를 이전 설치본의 최초 결함 원인으로 소급하지 않는다.
- CADisplayLink와 tick/그리기는 메인 루프를 사용한다. 지연 후 최대0.25초분을 따라잡는 업데이트가 추가되므로 정체를 증폭할 가능성은 있으나 실측 원인으로 확정하지 않았다. 60Hz 요청은 이미 설정돼 있다.

## 기존 성능 증거 재사용

`build/frame-performance/baseline.json`은 오디오를 제외하고 실제 UIKit drawRect를 오프스크린 실행했다. 120개 warm 프레임이며 타깃 bitmap2736×1260 생성 비용도 포함한다.

| 장면 | tick 평균 ms | draw 평균 ms | 16.67ms 초과 프레임 |
|---|---:|---:|---:|
| 타이틀 애니메이션 |0.004|10.040|0/120|
| 슬롯 기체 미리보기 |0.008|20.187|120/120|
| Stage01 사격 |0.119|19.506|120/120|

따라서 모든 메뉴가 실패한 것은 아니다. 슬롯 메뉴와 사격의 이 검사에서는 렌더 비용이 지배적이다. 소리를 제외해도 초과하므로 음향만 고치면 해결된다고 볼 수 없다. 이전 렌더 전용 O0/O2 비교는 게임 장면54–74ms 대4–6ms였지만 전체 코드 최적화의 비교이므로 특정 함수의 효과로 해석하지 않는다.

기존 manifest와 현재 HMMedia/project.yml 해시는 일치한다. HMGameView는 후속 기능 변경으로 불일치하므로 기존 수치를 최신 앱 전체의 재검사로 표시하지 않는다.

## 남은 확정 절차

이번 devicectl 조회에서 물리 iPhone Air는 unavailable이었다. 설치·실행·저장 변경은 하지 않았다. 아이폰 원인을 확정하려면 문제가 난 설치본을 식별하고 사격/슬롯 메뉴의 메인 스레드 시간을 렌더·최초 이미지 준비·음향 재시작으로 나눠 측정해야 한다. 최신 코드에는 이미 렌더·음향 변경이 있어 구버전과 섞으면 안 된다.

개선 우선순위는 이미지별 CPU 래스터/복사/생성을 줄이고 원본처럼 텍스처를 재사용하는 그래픽 경로를 만드는 것이다. 그 전에 동일 장면의 렌더 구간별 계측으로 실제 절감 대상을 정한다. 기존 원본 혼합·픽셀 규칙을 보존해야 한다. 이번 요청에서는 조사와 분리 실험까지만 수행했고 제품 수정·성능 해결·배포를 완료하지 않았다.
