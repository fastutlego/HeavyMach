## 추가 TODO의 권고안

**화면별로 기존 요소 재배치와 배경 확장을 함께 쓴다.** 타이틀의 배경·제목·문구는 분리되어 있고 슬롯/모드/미션 선택의 배경과 버튼도 분리되어 있다(`HMGameView.mm`, `HMMenus.mm`). 버튼·글자·로고는 원본 이미지와 비율을 유지하고 안전영역 기준으로 재배치한다. 하나의 그림인 배경은 원본을 보존하고 양옆에 별도 그림을 연결한다.

| 방법 | 적합한 화면 | 장점 | 비용·주의점 |
|---|---|---|---|
| 기존 요소 재배치·조합 | 메뉴, 슬롯/미션 선택, 분리된 UI | 원본 보존, 작업량 적음, 버튼 위치와 터치가 명확함 | 배경 한 장의 빈 영역까지 자연스럽게 채우기는 어려움 |
| 화풍을 맞춘 옆 그림 추가 | 타이틀·인트로·로딩 등 일러스트 중심 화면 | 원본 구도를 유지하면서 넓은 화면을 자연스럽게 채움 | 광원·원근·색·질감·이음새를 검수할 제작 작업 필요 |

먼저 실제 화면 목록을 만들고 각 화면을 두 방식 중 하나 또는 조합으로 분류한다. 대표 메뉴1개와 배경1개의 Air/Pro Max 시안을 비교한 후 나머지 화면으로 확대한다. 원본 늘이기·원본 잘라내기를 무변형으로 처리하지 않는다. 새 에셋은 원본과 분리해 보관한다.

**적 AI는 화면 폭과 관련된 값만 의도에 따라 보정한다.** 월드 이동 속도·탄속·충돌·원본 전투 거리까지 일괄 비례 확대하면 난이도가 달라진다. 고정값의 각 사용처를 스폰/활성, 전투 경계, 카메라, 이동 속도로 나누고 원본480과 확장 화면을 비교한다. 화면 가장자리까지 이동하려는 행동은 확장 전장 경계에 연결하고, 플레이어와 유지하는 전투 거리는 원본 규칙을 우선한다. 미션3-5 부분 수정만으로 전체 완료 처리하지 않는다.

**회전은 OS의 실제 가로 방향을 기준으로 연결한다.** 양쪽 가로 허용 설정은 이미 있다. 같은 폭·높이로180도 바뀌는 경우도 scene 방향 갱신으로 받아 HUD 안전영역·터치·틸트 필터를 함께 검사하고 필요한 경로를 고친다. 회전 중 남은 사격·이동 입력을 정리하고 세로 플레이는 허용하지 않는다.
