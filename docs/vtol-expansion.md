# 공중 적3종 추가

2026-10-27 사용자가 실물 사진·도면을 참조한 두 번째 시안을 채택했다. 야크141·해리어 GR3·F35B를 Apple 공용 코어와 자원에 연결했다. 설치·기기 검사의 최신 결과는 [현재 상태](current-status.md)에 기록한다.

## 원본 보존과 배치

`GameData::loadDirectory`는 원본만 읽는다. 앱의 `HMGameView`가 로드 직후 `addVTOLExpansion`을 한 번 호출한다. 원본 MAP/MCH 파일은 수정하지 않는다. 모든 맵의 원래 적1,182개 항목은 이름·좌표·보스 플래그·순서가 동일하다. 기존 배열 뒤에 새 항목을 추가해 원래 인덱스도 유지한다.

14개 서브미션에 총113대를 추가한다. 미션별 일반 헬기 평균에 따라 야크30대, 해리어41대, F35B42대다. 미션1·8과 Survival은 유지한다. [미션·수량표](public/vtol-art-and-loadout-20261027.md#미션별-추가-배치).

`VTOL.cpp`의 배치 설정은 원래 적의 X좌표 사이를 후보로 사용한다. 맵 양끝300, 보스 주변600을 제외하고 지형 높이+140에서 생성한다. 후보를 기존 간격과 선택된 추가 좌표 사이 거리로 비교해 구간 전체에 분산한다. 추가 지점 간 최소 간격은100이다. 기존 적을 옮겨 공간을 만들지 않는다. 모든 후보가 충분한지 로드와 자동 검사에서 확인한다.

## 무기·비행·표시

| 기체 | HP / 경험치 참고 | 재사용 무기 | 논리 폭 |
|---|---|---|---|
| 야크141 | Heli004: 210 / 10 | E_Wpn_ASM: 피해25, 단발 미사일 | 112 |
| 해리어 GR3 | Heli008: 400 / 25 | E_Boss_Wpn_01: 피해50, 기관포2발 | 108 |
| F35B | E0604: 900 / 60 | E_0604_Wpn: 피해100, 미사일2발 | 116 |

기존 machType1 헬기 비행을 사용한다. 새 기체만 수평 속도에 최대8도, 수직 속도에 최대3도를 더한 목표각으로 보간한다. 기존 적의 이동 상수는 바꾸지 않는다. 좌우 이동·상승·하강에 따라 자세가 변하고 정지하면 수평으로 돌아온다. 일시정지 때 회전과 배기 애니메이션 시간이 멈춘다.

기체별 난수 상태는 이름과 생성 좌표에서 정한다. 기체 생성, 비행, 무기 AI는 이 상태를 사용하며 기존 공유 난수를 쓰지 않는다. 배치 생성 자체는 난수를 사용하지 않는다. 추가 전투의 탄환·피격·아이템 결과는 기존 전투 처리를 따른다.

기체 길이는 Heli001 몸체99보다 길고 Heli006 몸체126보다 짧다. 높이·장착점·노즐·피격 범위도 같은 비율로 줄였다. 불꽃은 각 기체의 앞쪽 노즐을 제거하고 후방 노즐 하나만 남긴다. 장착점과 노즐은 기체 회전으로 변환한다. 미사일과 기관포 모두 변환된 장착점에서 발사한다. 피격 범위도 기체 회전을 따라 갱신한다. 기존 BulletEffect2의 첫32×8 영역을 배기로 재사용하고 상승/하강에 따라 길이를 바꾼다. 불꽃은 기체 이미지와 충돌 범위에 포함하지 않는다.

2026-10-27 후속 지시로 외곽선을 다듬은 `Art/VTOL/20261027-v3/`를 자원 번들에 포함한다. V2 원본은 보존한다. 이미지 로드 때만 게임의 논리 폭112/108/116으로 고품질 축소해 GPU에 올리며 비율을 유지한다. 이전의 폭512 텍스처를 작은 화면에 다시 축소할 때 생기던 가는 선·점의 불규칙한 표시를 줄인다. 큰 원본 텍스처3장을 계속 유지하거나 매 프레임 이미지를 변환하지 않는다. 저장·타이머·기존 원본 디코딩 경로는 유지한다.

## 검사

- `HeavyMachVTOLTests`: 원본1,182개 항목 보존,113개 추가,14개 맵, 재호출 중복 방지, 실제 발사·이동·회전·정지·파괴, 회전한 장착점에서 탄환 생성, 전투 중 추가 저장 없음.
- 20종 플레이어 무기×3종 기체의60개 피격 검사. 실제 탄환 충돌 함수를 호출하며 시작 위치를 피격 범위 안에 둬 피격 처리를 분리 검사한다. 자동 조준 명중률 검사와 구분한다.
- `HMAppleInputTests.testVTOLExpansionRendersAndUsesSeparateTextures`: 실제 기기 화면 비율,3종 자연 생성·렌더,게임 표시 크기의 텍스처, 저장 호출, 캡처. 최초 구현에서 동일 묶음의 키보드·터치·무기20종 검사도 통과했다. 이번 크기 수정은 관련 VTOL 검사만 다시 실행했다.
- `testVTOLSizeAndEdgeComparison`: Heli001·Heli006과 새3종을 같은 게임 크기로 수평/기울어진 자세에서 렌더한다. 두 기기에서 비교 캡처를 확인했다.

추가 적 밀도의 전체 미션 장시간 플레이, Mac 성능과 장시간 발열은 후속 검사다. 이번 짧은 렌더 비용을 실시간60fps 보장이나 장시간 안정성으로 표시하지 않는다.
