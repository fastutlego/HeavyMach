# 2026-10-25 일반 앱 설치와 확장 가장자리 실기기 검사

사용자가 치트 앱의 게임 화면이 폰 전체를 채우는 것을 직접 확인했다. 그 뒤 요청한 일반 앱 설치와 치트 앱의 가장자리 터치 검사를 수행했다. 게임 코드는 이번 검사에서 변경하지 않았다.

## 일반 앱

PaleMirror(iPhone Air, iOS27.0.1)에 최신 서명된 `HeavyMachRestored`를 업데이트 설치하고 실행했다. 표시 이름은 **Heavy Mach 1**, bundle은 `com.gelb2.heavymach.restored`다. 실제 타이틀에서 치트 버튼이 없는 것을 확인했다. 확장 캔버스 심볼은 있고 검증 조작부 클래스는 없다. 설치 전 Documents를 백업했고 설치 직후 실행 전 파일 해시가 모두 같았다.

설치 근거: `build/device-validation-runs/20261025T070435.627587Z/summary.json`. 일반 앱 debug dylib SHA-256: `a7563f3f9bbd65030ae72c21032b4973edb5045606bd75c2beb331514ec59dd7`.

## 치트 앱의 실제 입력과 탄환

Device Hub의 실제 폰에 CUA 터치를 전달했다. 설치된 치트 앱에 LLDB를 연결하고 `GobHvM_Player::setTap`, `setWeaponFire`, `GameSession::Impl::spawnBullet` 인수를 읽었다. 게임 상태나 조준값을 디버거로 변경하지 않았다. 검사 후 모든 중단점을 비활성화하고 프로세스를 detach했다. 치트 앱은 정지 메뉴에 남겼다.

논리 높이는320, 폭은 약694.857이다. 중앙 원본480의 범위는 x약107.429~587.429이며 아래 입력은 그 바깥이다. 화면 좌표는 당시 Device Hub 2200×1600 캡처 기준이다.

| 입력 | 실제 게임 입력 | 실제 결과 |
|---|---|---|
| 오른쪽 위 `(1438,720)` | `(665.142822,234.412704)` | 원작 계산 목표각0.160915255rad. 실제 사격 목표각0.160915270rad, 실제 월드 목표점 `(-293.405151,62.4127044)`. 후속 유지 입력에서 탄환8개의 각도0.160915270rad 확인. |

| 왼쪽 `(666,700)` | `(15.2380943,251.174606)` | 입력과 해제가 실제 게임까지 전달됨. 당시 탱크 뒤편(dx=-3.761877)이므로 탄환0개. 원작의 전방 조건 `dx>0`과 일치. |

오른쪽 위의 실제 사격 목표점은 터치와 플레이어 화면 위치·무기 회전 오프셋으로 계산한 `(-293.405122471,62.412704)`와 float 정밀도 범위에서 일치한다. 아래 첫 탄의 차이는 `Combat.cpp`의 매 tick 0.5 조준 보간과 각도 오차0.1rad 미만 발사 조건에 따른다. 터치 위치에 탄환을 강제로 생성하거나 즉시 적중시키는 방식은 아니다. 기존 포구·회전·무기별 탄도 규칙을 사용한다.

원시 근거: `build/normal-and-edge-check-20261025/physical-edge-events.jsonl`, 분석 `edge-summary.json`, 관측 코드 `edge_probe.py`. 초기 non-virtual thunk 중단점은 변수값을 읽지 못해 null 표본을 남겼다. 해당 위치를 비활성화하고 실제 함수 위치에서 얻은 유효 표본만 사용했다. 첫 짧은 누름에서는 디버거 지연으로 유효 탄환 표본을 얻지 못했고 유지 입력으로 재검사했다. 원시 실패 표본을 삭제하지 않았다.

이 검사는 좌표 전달·원작 조준·탄환 생성 검사다. 디버거 중단점이 실행을 지연시키므로 이 기록을 FPS·발열 측정으로 사용하지 않는다. 모든 무기·모든 기기 방향을 실기기에서 검사한 것은 아니다.
