# 조건별 검증 모드

## 2026-10-24 실기기 방향 조작 추가

치트 앱에 `← / 정지 / → / 기울기` 조작부를 추가했다. 기본값은 실제 기울기이며, 방향 버튼은 선택을 유지한다. 외부 키보드 방향키도 같은 입력을 만든다. 실제 아이폰과 시뮬레이터가 같은 HM_VALIDATION 경로를 사용하고 원본 50Hz 기울기 필터와 실제 Player 이동 코드를 통과한다. 일반 앱의 실기기 가속도 입력은 유지했다.

조작부는 `HMValidationControls` 별도 뷰다. Air에서는 게임 바깥 왼쪽 여백에 배치한다. 화면이 좁으면 상단에 배치한다. 듀오의 위 게임/아래 조작 배치는 아직 구현하지 않았으며 조작 뷰를 재배치할 수 있게 분리했다.

정지·키 해제·키 입력 취소·게임 메뉴·검증 패널·백그라운드 전환 때 수동 이동 입력을 해제한다. 감속은 원본 필터와 물리 처리를 따른다. 관련 XCTest 3/3 통과(`build/direction-controls-20261024/final.xcresult`). CUA로 저장 이어하기→오른쪽→정지를 눌렀고 실제 로그 x가 -1040에서 -306으로 이동한 뒤 고정됐다. 시뮬레이터 UI 검사이며 실제 폰 실행 결과는 아니다.

실제 iPhone용 무서명 빌드는 성공했다. 서명은 잠긴 로그인 키체인 때문에 errSecInternalComponent로 실패했다. 연결 후 서명·백업·설치·실행 준비는 [실기기 준비 문서](device-validation-ready.md)를 따른다. 현재 기기는 unavailable이며 이번 빌드를 실제 폰에 설치하지 않았다.


2026-10-24 사용자 지시: 내부 소스의 치트 모드로 레벨업, 레벨업 후 외형, 무기, 보스, 모든 미션 조건을 바로 설정하여 검증한다.

## 앱과 저장

구현한 앱은 별도 HeavyMachValidation target, bundle com.gelb2.heavymach.validation, 표시 이름 HM Validation이다. HM_VALIDATION 컴파일 조건에서만 설정 진입점을 제공한다. 일반 복원 앱 com.gelb2.heavymach.restored 및 기존 호환 앱과 저장 컨테이너를 공유하지 않는다. 이 문서는 구현·검사 전 항목을 통과로 표시하지 않는다.

시작 조건 생성과 기존 저장 재개를 구분한다. 재실행 검사는 조건을 다시 주입하지 않고 기존 슬롯을 읽는다. 설정 화면은 선택한 미션·스테이지·레벨·EXP·부품 단계·무기·위치를 로그로 남긴다.

## 검사 행렬

| 대상 | 주입하는 시작 조건 | 실제 코드로 실행할 동작 | 확인할 결과 |
|---|---|---|---|
| 레벨업 | EXP를 다음 임계치 직전으로 설정 | 실제 플레이어 경험치 획득 함수 실행 | 레벨 증가, EXP 게이지, Upgrade 화면 |
| 이동 업그레이드 | 각 차체 단계 0..5, 레벨업 직전 | 이동 선택→확인 | 단계 증가, 원작 부품 이미지·소켓, 이동/부스터 수치 |
| 방어 업그레이드 | 각 상체 단계 0..5, 레벨업 직전 | 방어 선택→확인 | 단계 증가, 외형, 최대 HP·게이지 |
| 공격 업그레이드 | 각 무기 단계 0..5, 레벨업 직전 | 공격 선택→확인 | 단계 증가, 외형, 실제 발사/대미지 |
| 단계 상한 | 각 부품 단계6 | 업그레이드 선택과 확인 | 원본 상한 처리, 데이터 초과 접근 없음 |
| 저장 | 위 실제 변경이 끝난 슬롯 | 저장→프로세스 종료→조건 재주입 없이 재실행 | 레벨·단계·무기·진행 유지 |
| 무기 | 원본 정의에 있는 플레이어 무기·탄약 | 선택→사격→탄약 소모→재장전 | 탄환/효과/충돌, 무기 교체·고갈·저장 |
| 미션 | 원본 매핑의 모든 mission/stage | 로드→실제 tick·입력·렌더 | 맵/적/지형/출구와 다음 진행 |
| 보스 | 원본 맵의 보스 직전 위치 | 원본 배치 생성·전투·피격·처치 | 보스 외형·AI·공격·처치 및 클리어 조건 |
| 원작 비교 | 같은 원본 데이터와 시작 조건 | 복원 앱과 원본 실행 결과 비교 | 위치·부품·수치·상태전이·영상·음향 차이 |

조건별 검사는 정상 획득 난이도나 전체 연속 플레이 성공을 자동 입증하지 않는다. 모든 미션을 로드했다는 결과와 모든 미션의 보스를 처치했다는 결과를 따로 센다. 원작과의 일치는 원본 결과와 직접 대조한 범위만 기록한다.

## 현재 증거

- 일반·검증 simulator 앱 빌드 성공. 두 앱의 device ARM64 무서명 빌드도 성공했다 (`build/native-validation-era-device.log`, `build/validation-device-unsigned.log`). 일반 복원 앱은 후속 Xcode Air 대상 서명까지 성공했으나 무료 프로필 앱 3개 제한으로 설치 실패했다. 후속 실기기 설치·실행·패널 진입은 성공했다. 아래 실기기 검사 한계를 따른다. 일반 앱 최종 executable/debug dylib의 검증 API·패널 심볼 및 fixture 문자열은 0개. 독립 검토에서 확인했다.
- CTest 8개 통과. 로그 `build/validation-core-ctest.log`. 검증 실행기는 이동·방어·공격 각 6단계, 합계 18회의 실제 경험치 획득→레벨업→강화 선택→확인→외형 tile 변경→저장 encode/decode→일반 start 복원을 검사했다.
- 후속 검증 타겟 검사도 통과했다. 18종의 레벨·EXP 저장 복원, 차체 이동 속도와 실제 이동 tick, 상체 최대 HP/현재 HP, 실제 탄환 충돌 피해를 검사했다. 모든 부품이 등급6일 때 세 강화 선택을 거절하고 기존 능력치를 유지했다. 원본 규칙상 방어 등급0→1은 HP256을 유지하며 이후 단계에서 증가한다.
- 원본 41개 스테이지 로드·각 3tick 및 보스 48개 배치의 접근 지형 계산 통과. 모든 미션 클리어·48보스 처치 검사는 아니다.
- Air iOS 26.5에서 패널로 레벨1/EXP299/기본 부품을 설정했다. ‘EXP 1 획득’을 눌러 실제 LV02·UPGRADE 화면을 확인했다. 이동을 선택하고 OK를 눌러 차체 외형이 변경되고 게임이 재개됨을 확인했다.
- SAVE & EXIT 후 검증 앱 프로세스를 종료·재실행했다. ‘저장 이어하기 (초기 조건 적용 안 함)’로 LV02·변경된 차체 외형을 다시 확인했다. 로그 `build/air-validation-play.log`, `build/air-validation-relaunch.log`.
- 검증 저장값은 EXP300/internal level1/body grade1이다. 일반 복원 앱은 EXP304/internal level1/weapon grade1이며 서로 다른 Documents 컨테이너다. 읽기 전용 확인 결과 `build/validation-save-isolation.json`.
- 일반 복원 앱에서 정상 전투 레벨2·공격 강화·재실행 플레이까지 확인한 기존 증거는 [verification](verification.md)에 보존한다.

후속 무기·보스 검사는 아래 기록을 따른다. 남은 범위는 실기기 레벨업·강화, 모든 무기 화면 비교, 모든 보스 처치, 전체 미션 진행, 원작 영상·음향·수치의 직접 비교다.

## 검증 시작 지면 수정

첫 접근 계산은 전체 collision vector를 검색했으나 실제 이동 코드는 x별 collisionCandidates를 사용한다. 이 차이로 검증 시작 지점에서 떨어지는 사례가 있었다. 검증 조건 생성기를 실제 후보 조회와 120tick 착지 검사로 수정했다. 가까운 480 범위에서 지면을 못 찾으면 원본 맵 왼쪽 전체에서 가장 가까운 안정 지점을 찾는다. Stage25와 Stage27은 보스까지 각각725·833 떨어져 시작하므로 실제 이동으로 접근해야 한다. 원본 지형·적 배치·체력·명중 규칙은 변경하지 않았다. 48개 안정 시작 지점 검사와 지면 없는 경우 저장 불변 검사를 통과했다. 이 결과는 보스 전투 통과 수가 아니다.

## 보스 v5 실제 전투 후속 결과

[보스 전투 v5](boss-battles-v5.md)에서48개 중33개 처치를 확인했다. 14개는 플레이어가 먼저 사망했고1개는 이전 보스가 남긴 진행 경계로 접근하지 못했다. 적 HP·위치·지형·명중 판정을 변경하지 않았고, 실패는exit1로 남겼다. 이전8승/40패와 v2~v4 결과도 build에 보존했다.

검증 입력은 실제 무기 회전 원점과 적 bounds 중앙을 사용한다. 탄도 보정, 원본 무기 선택, 이동·부스터, 레벨업 화면의 실제 확인 경로로 실행한다. 원본 자연 진행의 전투 이력까지 같다는 의미는 아니다. 보스 처치33개는 전체 미션 클리어33개를 뜻하지 않는다.

후속 회귀에서18강화·능력치·레벨/EXP 저장 복원, 무기20종의 사격·탄약·저장 후 재사격,41개 맵,48개 안정 시작 지점, 지면 없음 실패의 슬롯 불변을 통과했다. 결과는 `build/boss-v5-scenario-regression.log`다.

## 물리 Air 확인 범위

`HeavyMachValidation`의 Xcode 실기기 빌드와 strict/deep서명 검사, 설치·실행·패널·EXP299 시작을 확인했다. 기기 잠금으로 레벨업 결과 관측 전에 중단했다. 사용자의10분 이내 제한에 따라 실기기 추가 조작은 종료했다. 실기기 레벨업·강화·재실행 검증은 아직 미완료다. 일반 복원 앱의 기존 저장·기본 플레이 성공과 구분한다.
