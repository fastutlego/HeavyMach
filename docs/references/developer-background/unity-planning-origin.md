# PLANNING_GAMEDEV — 기획 정본 (L1 최상위)

> v0.1 · 2026-07-21 · 원 소스: 구글 문서 「게임 개발 논의 정리」(docs.google.com/document/d/1yELowtR2H_oWgTM_ayd2h6a5ESdzcSrxjNaHwxCi5WQ). 이 파일이 로컬 정본이며 이후 변경은 여기에만 반영한다. 기획과 코드가 불일치하면 기획이 정답.

## 1. Why

iOS/웹 개발 자산(SOLID·모듈화·Clean Architecture·AI 하네스 운영)을 게임 개발로 전이해, AI 파이프라인(코드·이미지·오디오)을 지휘하며 **1인 개발로 완성도 있는 싱글플레이 아케이드 게임**을 만든다. 배우는 목적이 절반: 유니티·C#·게임 아키텍처를 실전으로 습득한다.

## 2. 프로젝트 후보와 스코핑

| 후보 | 내용 | 판정 |
|---|---|---|
| ① HeavyMach1 재해석 | 2D 횡스크롤 틸트 탱크 슈터. 오리지널 IP로 재해석 | **가능** (복원형 조건 충족, 검증 자동화 가능) |
| ② 3D 아케이드 공중전 | 에이스컴뱃식 싱글 공중전. 기체 오리지널 디자인 | 조건부 가능 (에셋·튜닝 비용 큼, 프로토타입은 사정거리 안) |

- 공통 스코핑: **싱글플레이 전용, 아케이드 지향** (멀티·라이브 서비스 배제 — ADR #04)
- **착수 확정: ① 2D 틸트 탱크** (ADR #13). 목표 = HeavyMach1(machDefense — **HeavyMach2 탑다운 아님**)과 같은 조작감·기능·게임 기본 구조를 유니티로. 후보 ②(3D 공중전)는 ① 완료 후 재론
- 원작 참조 스펙(§7 법적 방침 내에서 구조만): 틸트 좌우 이동(기울기 비례 속도), 탭 조준·발사, 레버 탭 (더블)점프, 무기 다종(머신건·샷건·곡사포·미사일·레이저·핵) 제한 수량, 6미션 30~60스테이지, 플레이어·적 탱크 간 충돌 판정 없음(통과) — 재해석 시 개선 여지: 충돌 판정·오브젝트 풀링·FixedUpdate 규율

### 2026-07-22 #13 · 착수 프로젝트 = 2D 틸트 탱크 (HeavyMach1 재해석)
- 결정: 후보 ① 확정 착수. 목표는 HeavyMach1과 같은 조작감·기능·게임 기본 구조를 유니티로 구현. 참조 대상은 machDefense 계열 원작(횡스크롤 틸트)이며 **HeavyMach2(탑다운)가 아님**. IP는 ADR #03대로 전부 오리지널. 후보 ②(3D 공중전)는 보류 — 재론은 사용자가 꺼낼 때만
- 사용자 트리거: "2d 틸트 탱크 / 목적: HeavyMach1 (machDefense, HeavyMach2 아님)과 같은 조작감, 기능, 게임 기본 구조를 갖춘 게임을 유니티로 만들기"
- 영향: 다음 단계 = 유니티 설치 → game/ 프로젝트 생성 → HM1 기능 명세(gamedev-planner). 조작감(틸트 손맛)은 §0.4대로 기계 판정 불가 — 사용자 검수 루프 필수
