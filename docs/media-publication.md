# 플레이 영상·README 이미지 작업

사용자가 게임 플레이 영상을 제공하면 이 절차로 스크린샷·클립과 README 설명을 만든다. 2026-10-27에 영상 2개를 받아 [이미지 8장과 클립 3개](public/gameplay-media-20261027.md)를 추출했다. 원본은 Git 제외 폴더에 보존했고 파생 파일의 출처·시각·캡션을 기록했다.

## 원본과 장면 기록

원본 영상은 Git 제외 `build/media/<작업명>/original/`에 보존하고 SHA-256을 기록한다. 편집은 `derived/`에 새 파일로 출력한다. ffprobe로 길이·해상도·회전 메타데이터·프레임률·음향 트랙을 확인한다. 본문에 쓰는 앱 종류·기기·버전은 제공 정보와 실제 화면에서 확인하며 모르는 값은 만들어 넣지 않는다.

[장면 명세 예시](media-scenes.example.json)에 원본 해시, 촬영 조건, 시작·종료 시각, 대표 프레임 시각, 관찰한 동작, 캡션, 파생 파일을 기록한다. 예시는 빈 양식이며 실제 영상의 시각이나 결과가 아니다.

영상 전 구간에서 추출한 프레임을 순서대로 보고, 후보 구간은 프레임 간격을 좁혀 이동·점프·사격·무기 전환·미션 클리어가 드러나는 장면을 고른다. 치트 패널이 있는 장면은 치트 앱이라고 표시한다. 원본·복원 비교 장면은 실제 두 판본의 영상이 있을 때만 만든다. 한 영상으로 수정 전후를 꾸미지 않는다.

## 추출

필요한 도구는 `ffmpeg`, `ffprobe`다. 아래 경로·타임코드는 작업자가 실제 파일과 장면 명세로 바꾼다. `-n`은 기존 출력을 덮어쓰지 않는다.

```sh
ffprobe -v error -show_format -show_streams -of json "$HM_VIDEO" > "$HM_WORK/probe.json"
ffmpeg -n -i "$HM_VIDEO" -ss "$HM_FRAME_TIME" -frames:v 1 "$HM_WORK/derived/gameplay.png"
ffmpeg -n -i "$HM_VIDEO" -ss "$HM_CLIP_START" -t "$HM_CLIP_DURATION" \
  -c:v libx264 -crf 20 -pix_fmt yuv420p -c:a aac -movflags +faststart \
  "$HM_WORK/derived/gameplay.mp4"
```

타임코드는 원본의 재생 시간 기준이다. 원본 비율·게임 진행 속도와 음향을 유지한다. HUD·탄착점·적 이동을 설명할 때 필요한 화면을 자르지 않는다. 회전·HDR·색 변화가 있으면 원본과 추출 프레임을 비교해 수정한다. 긴 영상 전체를 GIF로 바꾸지 않는다. 반복 움직임이 꼭 필요한 짧은 구간만 GIF 후보를 만들고, 용량·글자 가독성을 본 뒤 채택한다.

## README 배치

2026-10-27 사용자 지시: 선정한 이미지 8장을 모두 포함한다. [현재 구성안·GIF 계획·GitHub 절차와 스킬 조사](public/gameplay-media-20261027.md)를 따른다. 현재 PNG8장·GIF2개·MP4 3개를 README에 배치했다. GIF는 768×354·12fps로 만들었고 원래 속도를 유지했다.

| 위치 | 자료 | 설명 |
|---|---|---|
| 제목·짧은 소개 아래 | 대표 전투 화면 한 장 또는 짧은 동작 GIF | 어떤 게임인지 바로 보이는 장면 |
| 플레이 소개 | 현재 선정한 이미지 8장 전체를 기능별로 배치 | 이미지마다 한 문장. 실제로 보이는 동작을 쓴다. |
| 일반·치트 앱 설명 | 일반 화면과 검증 패널 화면 | 두 앱의 차이를 실제 화면과 연결 |
| 복원 과정 링크 근처 | 실제 수정 전후가 있는 경우에만 비교 이미지 | 비교 조건·수정 대상을 캡션에 적음 |
| 영상 링크 | 대표 프레임을 누르면 클립으로 이동 | 재생 가능한 링크를 직접 확인 |

이미지는 원본 비율로 표시하고 상세 화면은 원본 크기로 열 수 있게 연결한다. 넓은 화면에서는 필요할 때 2열 표를 쓰며, 좁은 화면에서 HUD를 읽기 어렵다면 한 열로 바꾼다. 배지·장식·문구를 게임 화면 위에 합성하지 않는다. 아직 없는 영상·이미지의 빈 틀을 README에 게시하지 않는다.

GitHub의 [상대 이미지 경로와 Markdown 안내](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax)를 사용한다. 저장소 이미지에는 상대 경로를 쓰고, 영상은 우선 대표 이미지와 클립 링크로 연결한다. 인라인 재생을 적용하면 실제 GitHub 화면에서 재생을 확인한다. GitHub의 [첨부 형식·용량 안내](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/attaching-files)는 PNG·GIF·MP4 등을 지원하며 H.264를 권장한다. 게시 시점의 제한을 다시 확인한다.

## 파일과 문서 연결

채택된 이미지와 명세는 `docs/public/media/`에 추가한다. PNG·JPEG는 저장소의 Git LFS 설정을 따른다. 클립은 크기와 게시 경로를 확인해 저장하고, 원본 영상 전체를 일반 Git에 추가하지 않는다. 임시 파일 경로나 만료되는 URL을 README의 링크로 쓰지 않는다.

같은 이미지·클립 ID를 README, 이미지 색인, SaaS 집필 안내에서 사용한다. SaaS 담당 세션은 원본 해시·타임코드·촬영 조건과 함께 가져간다. 원본이 개인 로컬 경로에만 있으면 출처 메타데이터와 채택된 파생 파일만으로도 어느 장면인지 확인할 수 있게 한다.

마감 때 원본 해시 보존, 파생 파일 재생·비율·색·오디오, 이미지 링크·대체 텍스트, GitHub의 넓은/좁은 화면, 사이트·다운로드와 캡션 일치를 확인한다. 잘라낸 하이라이트를 전체 미션·성능 검사의 근거로 바꾸어 설명하지 않는다. 작업 브랜치→develop→main 순서로 반영하며 v0.9 태그를 이동하지 않는다.

## 영상 판독과 스킬 조사 — 2026-10-27

현재 환경에서 수행 가능하다. Mac의 `/opt/homebrew/bin/ffmpeg`와 `ffprobe`는 8.1.2이며 `select`·`tile` 필터 도움말도 실행해 확인했다. 제공된 영상 파일을 FFmpeg로 프레임·짧은 클립으로 추출하고, 이미지 판독 도구로 장면을 확인한다. 영상 전체를 한 번에 이해했다고 가정하지 않고 구간별로 검토한다. 이 조사는 영상 수령 전에 수행했다. 이후 영상 2개를 받아 아래 절차로 후보를 만들었다.

| 도구·스킬 | 맡길 일 | 확인 상태 |
|---|---|---|
| ffprobe | 길이·해상도·회전·프레임률·영상/음향 트랙 조사 | 설치·버전 확인. [공식 문서](https://ffmpeg.org/ffprobe.html) |
| FFmpeg의 fps/select/tile/thumbnail | 일정 간격·장면 변화 후보 추출, 프레임 목록 이미지, 정확한 시점 캡처·구간 편집 | 설치·필터 확인. [공식 필터 문서](https://ffmpeg.org/ffmpeg-filters.html) |
| `view_image`와 이미지 판독 | 추출 프레임에서 HUD·탱크·탄환·적·메뉴의 상태를 보고 장면 선정 | 현재 세션에서 게임 캡처 판독에 사용한 도구 |
| `write-project-text` | 기능 설명·캡션·README 문구, 실제 장면과 설명 대조 | 프로젝트에 설치됨 |
| `present-game-artifacts` | 선정 결과를 기존 보고 사이트에서 검토할 수 있게 전달 | 프로젝트에 설치됨 |
| `n0an/ffmpeg-skill` | 변환·구간 편집·썸네일·장면 변화 프레임 목록의 FFmpeg 명령 참고 | [제작자 SKILL.md](https://github.com/n0an/ffmpeg-skill/blob/main/ffmpeg/SKILL.md) 조사. MIT, v1.0. 미설치 |

외부 스킬은 명령 작성 참고 자료다. 게임 장면의 의미와 설명할 기능을 고르는 일은 추출 프레임을 보고 수행한다. 현재 과제에는 기존 도구·절차가 있으므로 별도 스킬 설치가 선행 조건은 아니다. 영상 캡처에 생성형 이미지 편집을 적용하지 않는다.

### 장면을 고르는 순서

1. 원본 영상의 정보와 해시를 기록한다. 전체 재생 구간을 빠짐없이 일정 간격으로 추출해 타임코드가 대응하는 검토용 프레임 목록을 만든다. 구간 길이와 동작 속도에 따라 간격을 정한다.
2. 화면 구성·입력 반응·무기 차이·적 움직임·메뉴 전환이 드러나는 구간을 고른다. 장면 변화 검출은 보조로 쓴다. 같은 배경에서 계속 싸우는 구간은 일정 간격 추출을 함께 사용한다.
3. 후보 앞뒤를 더 촘촘하게 추출해 동작의 시작·진행·결과를 확인한다. 점프와 탄착처럼 빠른 동작은 필요한 구간의 모든 프레임까지 확인한다. 화면이 전환되거나 폭발이 HUD를 가린 순간은 대표 이미지 후보와 구분한다.
4. 정지 화면으로 설명되는 기능은 PNG/JPEG, 움직여야 이해되는 기능은 짧은 MP4 또는 제한된 GIF로 만든다. 대표 전투 장면, 서로 다른 무기, 자동조준 ON/OFF, 새 기체의 진입 등 영상에 실제로 담긴 항목을 선정한다.
5. GitHub README에는 사용자가 채택한 8장을 모두 배치한다. Sass에는 같은 장면 ID·원본 크기 이미지·클립·타임코드·캡션 후보·대체 텍스트를 제공한다. Apps/Mags 본문은 Sass 담당 세션이 이 자료로 작성할 수 있게 한다.

선정 기준은 작은 크기에서도 전투 상황과 HUD를 읽을 수 있는가, 설명할 기능이 보이는가, 다른 이미지와 같은 장면을 반복하지 않는가다. 녹화 영상만으로 입력 지연이나 실제 FPS를 정밀 측정했다고 쓰지 않는다. 현재 GitHub의 영상 첨부 안내는 호환성을 위해 H.264를 권장한다. [GitHub 공식 안내](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/attaching-files).

최종 인계물은 `media-scenes.json`, 기능별 이미지·클립, 파일별 캡션/대체 텍스트와 사용 위치를 담은 `README.md`다. 원본·장면 ID·파일 경로를 연결해 GitHub와 Sass가 같은 장면을 재사용한다.
