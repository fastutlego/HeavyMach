# HeavyMach 웹(WebAssembly) 이식

2026-10-28 사용자 지시: 프로젝트를 확인해 Wasm으로 이식하고 웹에서 실행한다. 작업 브랜치는 `porting/wasm`이다.

## 현재 상태

일반 앱(HM_VALIDATION=0)의 웹 빌드가 동작한다. `Sources/Core`의 C++ 게임 코어를 그대로 컴파일하고, iOS 플랫폼 계층(Objective-C++)을 같은 동작의 C++로 옮겨 `Sources/Web`에 두었다. Chrome 156(macOS, 헤드리스)에서 타이틀→슬롯→모드→미션→1-1 진입, 이동·사격·점프, 자동조준 A 전환, 일시정지, 저장과 새로고침 후 복원을 자동 검사로 확인했다. 코어 회귀 검사 21개도 Wasm으로 컴파일해 Node에서 모두 통과했다.

2026-10-29: 자원을 20MiB 이하 묶음 3개로 나눴고, 4:3보다 세로로 긴 브라우저 창에서 화면이 위아래로 늘어나던 문제를 고쳤다. 사용자 지시에 따라 fastutle-site main에 반영해 https://fastutle.com/game/heavy_mach/ 로 배포했다(커밋 `0be8788`). 배포된 주소에서 브라우저 검사가 통과했다. [사이트 테스트 배치](#사이트-테스트-배치).

실제 휴대폰 브라우저의 틸트·터치·소리, Safari·Firefox, 치트 웹 빌드는 아직 확인·구현하지 않았다. [남은 과제](#남은-과제).

## 구조

```
Sources/Core/*.cpp ──(변경 없음)──┐
Sources/Web/                      ├─ em++ → index.wasm / index.js
  WebMain.cpp      진입점·WebGL2 컨텍스트·내보낸 입력 함수
  WebGameView.cpp  HMGameView 번역: 프레임 진행·화면 전환·입력 분배·저장
  WebMenus.cpp     HMMenus 번역: 슬롯·모드·미션
  WebGameHUD.cpp   HMGameHUD 번역: HUD·일시정지·업그레이드·결과 버튼
  WebMedia.cpp     HMMedia 번역: stb 디코딩·자원 범위·그리기 요청
  WebGLRenderer.cpp HMGLRenderer 대응: WebGL2에서 GLES 1.1 상태 재현
  WebAudio.cpp     HMOpenALAudio 번역: Emscripten OpenAL
Web/shell.html     캔버스·DOM 입력·IndexedDB 연결
Web/CMakeLists.txt 빌드
Web/tools/package_assets.py 자원을 20MiB 이하 묶음으로 패키징(hm-assets.js, hm-assets-<n>.data)
```

번역한 C++은 원본 메서드 이름·순서·수치·binary32 변환·원작 주소 주석을 유지한다. 호출 흐름은 iOS와 같다: WebGameView → GameSession/World → RenderCommand → Media → GLRenderer. 게임 규칙의 복사본은 없다. 메뉴·HUD·프레임 조립은 현재 iOS 소스와 웹 소스에 각각 있다. Android 계획의 `Sources/Platform` 공통화가 끝나면 한 벌로 합칠 대상이다.

## 플랫폼 연결

| 항목 | iOS | 웹 |
|---|---|---|
| 그래픽 | OpenGL ES 1.1 고정 파이프라인 | WebGL2 셰이더로 GL_REPLACE/MODULATE(RGBA·RGB565), 원본 블렌드 표, 가위 영역, DITHER, float 행렬 스택을 재현 |

| 장면 버퍼 | ceil(W)×ceil(H) RGBA8 renderbuffer → 복사 텍스처 → drawable | 같음(glCopyTexSubImage2D, LINEAR/CLAMP 최종 사각형) |
| 스프라이트 텍스처 | POT, LINEAR/REPEAT, touchHLE 감마 왕복, RGB565 패킹 | 같음 |
| 선 그리기 | glLineWidth(2) | WebGL은 선 폭 1로 제한되어 2픽셀 폭 사각형으로 변환 |
| 신규 기체 축소 | CoreGraphics 고품질 보간 1회 | 면적 평균 축소 1회(VTOL·럭스루나에·자동조준 버튼 시트) |
| 프레임 | NSTimer 기한, 한 번에 1틱 | requestAnimationFrame마다 기한 확인 후 최대 1틱. 기한보다 1/4 간격 이내로 이른 콜백은 그 틱으로 처리. 밀린 틱 보충 없음 |
| 센서 | CoreMotion 50Hz | DeviceMotion(m/s²)을 CoreMotion g 부호로 바꿔 50Hz 기한마다 샘플. screen.orientation.angle 90을 LandscapeRight로 보고 X/Y 반전 |
| 터치·마우스 | UITouch | Pointer Events, pointerId별 소유·취소 처리 |
| 키보드 | HID usage | KeyboardEvent.code → HID usage 표 |
| 저장 | Documents/HvM.dat 원자 쓰기 | IDBFS `/persist/HvM.dat`, 임시 파일→rename 후 IndexedDB 동기화. 정상 저장 지점 4곳만 |
| 설정 | NSUserDefaults | localStorage `HeavyMach.KeyboardBindingsV1`, `HeavyMach.AimModeV1` |
| 음향 | OpenAL Soft 1.22.2 | Emscripten OpenAL(Web Audio). 31개 WAV 버퍼·소스 재사용, 위치→stop→play 순서, inverse distance clamped |
| 비활성 | resign/become active | 탭 숨김·창 포커스 상실·pagehide·휴대폰 세로 화면에서 정지, 복귀 후 메뉴에서 재개 |

## 범위에서 뺀 부분

- 치트 검증 패널·방향 버튼·검증 저장(HM_VALIDATION=1). 웹 빌드는 일반 앱만 만든다.
- HMGameView의 CPU 비교 래스터(drawRect)와 Mac 전용 분기. 제품 렌더 경로가 아니다.
- 원본 홈페이지 버튼(103)은 새 탭으로 연다.

## 빌드와 실행

```sh
brew install emscripten git-lfs
git lfs install --local && git lfs pull
python3 tools/verify_build_resources.py
emcmake cmake -S Web -B build/web -DCMAKE_BUILD_TYPE=Release
cmake --build build/web
python3 -m http.server 8765 --bind 127.0.0.1 --directory build/web/dist
```

브라우저에서 `http://127.0.0.1:8765/`를 연다. `?trace=1`을 붙이면 1초마다 HM_TRACE 줄을 콘솔에 출력한다. 화면을 한 번 클릭하면 창이 활성화되어 게임이 진행된다.

자동 검사:

```sh
cd Web/tests && npm install
node browser-smoke.mjs http://127.0.0.1:8765/ ../../build/web/smoke
TOUCH=1 node browser-smoke.mjs http://127.0.0.1:8765/ ../../build/web/smoke-touch
```

코어 검사(Wasm):

```sh
emcmake cmake -S . -B build/web-core-tests -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_CXX_FLAGS=-fwasm-exceptions \
  -DCMAKE_EXE_LINKER_FLAGS="-fwasm-exceptions -sNODERAWFS=1 -sALLOW_MEMORY_GROWTH=1 -sSTACK_SIZE=8MB"
cmake --build build/web-core-tests && (cd build/web-core-tests && ctest)
```

## 검사 중 고친 문제

- IDBFS를 전역 이름으로 찾지 못해 부팅이 멈췄다. `-sEXPORTED_RUNTIME_METHODS`에 IDBFS를 넣고 `Module.IDBFS`로 마운트했다.
- pointerdown의 preventDefault가 마우스의 mousedown을 막아 Web Audio 재개가 일어나지 않을 수 있었다. pointerdown에서는 기본 동작을 막지 않는다.
- 휴대폰 세로 화면에서 안내가 게임을 덮어도 게임이 계속 진행됐다. 세로 상태를 비활성으로 처리한다.
- 2026-10-29 사용자 보고: 데스크톱 브라우저 창이 세로로 길면(690×805) 화면이 이상했다. 논리 화면이 480×560이 되어 HUD와 월드가 iOS에 없는 비율로 놓였다. `WebGameView::updateCanvasGeometry`가 CanvasGeometry에 넣는 높이를 가로×3/4 이하로 제한하고, `Viewport::drawable`이 남는 높이를 여백으로 둔다. 같은 창에서 480×360과 전 과정 통과를 확인했다. 코어·iOS 코드는 그대로다.

## 확인한 공용 키보드 동작

키보드 사격의 첫 조준점은 플레이어 위치 +100이다(`ensureKeyboardAim`, iOS·Mac과 공용). 원작 `setTap`(0x1d300)은 포신 위치에서 100단위 이상 떨어진 탭에만 사격한다. 포신 위치는 차체 흔들림에 따라 움직이므로, 조준키를 쓰지 않고 바로 사격하면 사격이 시작되지 않는 경우가 있다. 헤드리스 검사에서 6회 중 2회 재현했다. 조준키로 조준점을 옮긴 뒤 사격하면 10회 모두 사격했다. 웹은 iOS와 같은 동작을 유지하고, 공용 수정은 [TODO](usability-todo.md#hm-keyboard-aim-threshold)로 넘겼다.

## 남은 과제

- 실제 iPhone Safari·Android Chrome에서 틸트 방향(양쪽 가로), 멀티터치, 소리, 안전영역, 성능 확인. DeviceMotion 부호·축 변환은 명세 기준 구현이며 실기기 검사 전이다.
- Safari·Firefox 데스크톱 확인. 실제 스피커 출력 확인.
- 90/120Hz 표시 장치의 틱 수 계측.
- 치트 웹 빌드 여부 결정과 구현.
- 원작 자원(46MB)을 fastutle.com에 계속 공개할지 결정. 원작 자원의 재배포 허락은 미확인이다(docs/public/github-licenses-and-badges-20261028.md).
- 실제 휴대폰에서 https://fastutle.com/game/heavy_mach/ 실행 확인.
- iOS·웹·Android가 공유할 `Sources/Platform` 추출.
