# 클리어 전체 화면·필살기 목표점 수정 — 2026-10-25

## 사용자 보고와 원인

사용자는 클리어 일러스트 밖으로 월드가 보이고, 초기 지급 필살기3종의 상당수가 터치점 대신 탱크 뒤에 떨어진다고 보고했다. 이전 실기기 검사 `cb6d49ca`는 기본 무기 일부 사격만 검증했으며 이 보고의 필살기 정상 확인이 아니었다.

- 결과 화면: 확장 게임 화면 위에서 일러스트에도 중앙480 HUD의 offset/scale/clip을 적용했다. 그림 밖의 월드를 가리지 못했다.
- 필살기: 확장 화면 `HMGameView.routeTouches`가 해제 때 `(0,0)`을 보냈다. 원작 `GobHvM_Player.setTap 0x1d300`은 해제에서도 월드 목표점을 갱신한다. `GobMachWeapon.tick 0x11e64`는 이미 시작된 연사를 계속하며 각 탄환 생성 때 목표점을 읽는다. 따라서 앞의 탄과 해제 뒤 남은 탄이 다른 곳을 향했다. 화면 밖 해제의 `(-1000,-1000)`과 정지·키 해제의 고정 좌표도 같은 위험이 있었다.

원본 근거: `Analysis/functions/0x1d300.pseudo.c`, `.asm`, `0x11e64.pseudo.c`, `.asm`. 디컴파일 CGPoint 인수 표기는 기존 ARM ABI 해석과 `Player.cpp`를 함께 따른다. `Combat.cpp`의 type5 분산·생성 위치·탄약·데미지는 변경하지 않았다.

## 수정

정상 터치 해제는 실제 좌표를 전달한다. 취소·화면 밖 종료·키 해제·앱 중단/정지는 `GameSession.releaseFire`로 발사 플래그만 해제한다. 진행 중 연사의 목표점과 발사 수는 유지한다.

결과 일러스트를 HUD clip 밖의 전체 캔버스에 비율 유지 cover로 그린다. 사진의 위아래 일부는 화면 비율에 맞춰 잘릴 수 있다. 그림 뒤에는 HUD 변환·clip을 복원해 글자·버튼·중단 메뉴의 배치와 입력을 보존한다. 일반 HUD나 월드의 draw/버튼 등록을 임의 생략하지 않는다. 원본480 표시도 유지한다.

단색 전체 화면 검사에서 확장 이미지의 맨 왼쪽·오른쪽 1열씩(총640픽셀)이 LINEAR/REPEAT의 검정 POT 여백을 섞는 문제도 재현했다. cover 계산에 원본 이미지 바깥 texel 중심까지의 범위를 사용해 이 줄을 없앴다. 원본 자원 파일이나 GL 필터 설정은 바꾸지 않았다.

## 검증 결과

환경: 전용 `HeavyMach-Canvas-Test`, iOS26.5, Simulator Apple Software Renderer. 실제 iPhone 검사가 아니다. 증거 루트 `build/weapon-result-fix-20261025/`.

- `verified.xcresult`, `verified.log`: iOS14/14 통과. 실제 View 입력·GameSession 연사, 결과GL, 메뉴·패시브 수명 검사 포함.
- 모든 원본 플레이어 무기20종 × View 크기480×320/912×420/956×440 × 6입력 = **360조건 통과**. 원본480·Air·Pro Max 화면 크기의 기하 입력으로 검사했다.
- 6입력: 중앙 부근에서 드래그 후 정상 해제, 오른쪽 추가 영역 정상 해제, 화면 밖 해제, 취소, 정지/재개, 키 해제. 실제 첫 탄 뒤 해제하고 원본 연사 전체를 완료한다. 목표점·type5 분산 방향·전체 발사 수·탄약 1회 소모를 검사했다. 무적/무한탄약은 사용하지 않았다. 레벨99·몸체/상부6·무기0의 검증 초기 조건이다.
- 결과 이미지15개 × 크기3종 = **45조합**. 원본 사진 비교, 원본 치수의 단색 불투명 텍스처로 바깥 영역 모든 픽셀의 정확한 색상 일치, 결과 버튼 터치 후 step3 전환을 검사했다. 단색은 테스트 프로세스 GPU에만 넣고 원본 파일을 변경하지 않았다. 별도의 기존 원본JPEG15개 중앙 표시 검사도 그대로 통과했다.
- `core-tests.log`: 코어17/17 통과.
- `normal-device-final.log`, `validation-device-final.log`: 일반·치트 ARM64 iPhone **미서명 빌드** 성공. `build-manifest.json`에 최종 dylib SHA-256 기록. Simulator 치트 빌드 설치·실행 성공.
- Device Hub에서 수정된 치트 앱을 직접 열고 모든 무기 지급·필살기 선택 후 오른쪽 확장 영역에 터치했다. 해당 오른쪽 영역의 낙하 효과·폭발과 정지 메뉴를 화면으로 확인했다. 마지막 상태는 시뮬레이터 일시정지다. 자동 검사 외에 20종을 모두 손으로 조작했다고 보고하지 않는다.

## 실패·진단 보존

`before-runtime.xcresult`에서 실제 목표점 변경과 결과 화면 외곽 불일치를 재현했다. 최초 `before.log`는 새 테스트 코드의 CGPoint 속성 직접 수정 컴파일 오류이며 제품 오류와 구분한다. 컴파일 오류 수정 후 재현을 실행했다.

사진 전체 exact 비교 중 일부 채널에서1 차이가 났다. `reference-repeat.log`는 동일한 직접 렌더 두 번에서도 `GameLoading_04E.jpg` 원본480의3587채널에 최대1 차이가 있음을 기록했다. `result-no-dither.log`에서 DITHER를 꺼도 차이가 남았으므로 디더링을 단독 원인으로 확정하지 않는다. 사진 비교에는 기존 `HMGLReferenceTests`의 독립 CGL 계약인 채널당1을 적용했고, 화면 가림은 별도 단색 exact 검사로 검증했다. 기존 원본 픽셀 검사의 기준과 제품 GL 설정을 변경하지 않았다.

`final.xcresult`는 단색 검사에서 실제 POT 여백640픽셀 문제를 찾은 실패다. 해당 cover 계산 수정 후 `verified.xcresult`에서45조합 전부 통과했다. 모든 중간 로그·결과를 보존한다. 독립 검토에서 최종 필수 결함은 발견되지 않았다.
